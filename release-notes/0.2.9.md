# DSH 集成桌面端 0.2.9

把官方 DeepSeek Harness 内核装进原生 Electron 外壳。**外壳不修改内核的任何文件**；
内核由外部独立安装与升级 —— 升级内核不需要动外壳。

> 这一版两件事：
> ① **侧边栏的文件树，现在能"真的打开"了**；
> ② **「更新」栏里多了一个检查内核更新的按钮**（从官方渠道查）。
> 两件都指向同一个主题：**外壳与内核互不干扰** —— 这也是本版要证明的事。

> ⚠️ **必须重装一次**（不是"重启客户端"）：外壳代码是打进安装目录的，重启不会换代码。

## 一、侧边栏文件：从"只能看"到"能真正打开"

用户原话：「我真的可以在侧边栏点击文件夹，点击文件来打开它（也就是点击这个动作，
有两个功能，一个功能是打开，然后读它，另外一个功能就是，相当于在文件管理器中
点击他的能力）」

以前侧栏文件树**只有一种点击**：在侧栏里把它读出来预览。想用别的程序打开它、
想在资源管理器里找到它，都做不到 —— 只能自己去文件管理器里一层层翻。

现在每一行多了**两个动作**，而**原来的单击一点没变**：

| 手势 | 结果 |
|---|---|
| **单击**文件 / 文件夹 | 照旧**在侧栏里读它**（内核自带的行为，一个字节都没改） |
| **鼠标移到那一行** | 行尾浮出小图标：`↗ 用默认应用打开` / `📂 在文件资源管理器中显示` |
| **右键任意一行** | 菜单：用默认应用打开 / 在文件资源管理器中显示 / **复制路径** |

- 文件夹的单击仍然是展开 / 折叠（内核行为）；它的"真打开"走图标与右键菜单。
- 「用默认应用打开」= `.txt` 进记事本、`.md` 进你关联的编辑器……由系统决定。
- 「在文件资源管理器中显示」= 打开资源管理器并**选中**它（不是只打开上级目录）。

### 为什么这事儿只有外壳能做

右侧边栏是**内核自带的 Web 插件**（`dsh-client-ui-sidebar-right` + `-sidebar-files`），
不是我们的东西。但它的每一行**本来就带着绝对路径**
（`<li data-files-entry="file" data-files-path="C:\...\note.txt">`），
所以外壳可以只在旁边加控件 —— **不需要碰内核一个字节**。

而"用默认应用打开"这件事，**网页做不到**：渲染进程里拿不到 Electron 的 `shell`。
内核虽然有一条现成的"打开路径"通道（`sessionController.openWorkspacePath`），
但那是**宿主半边**的一等公民服务，外挂客户端插件够不着。
⇒ 落点只能是外壳（注入官方页面 + 外壳 IPC），这与 0.2.3 的三页切换同一条思路。

## 二、新增：检查内核更新（官方渠道）

用户原话：「我们这个版本的目的就是内核更新不会跟外核发生冲突。加一个检查按钮，
可以检测内核更新，要从官方渠道下载。」

**「更新」栏里现在有两件事，刻意分开**：

|  | 升什么 | 从哪来 |
|---|---|---|
| 上面那段「检查更新」 | **外壳**（我们自己那个 exe） | 本项目的 GitHub Releases |
| 下面新增那段「检查内核更新」 | **内核**（`@deepseek-ai/dsh`） | **官方渠道**：npm registry |

内核那一段会做的事：

1. **显示本机内核** —— 版本 + **它来自哪里**（本机是「全局 npm」）+ 完整路径。
   开机就显示，不用点检查。而且它报的是**这个客户端真正会去启动的那一个**
   （走的是 `kernel.js` 同一条发现链，不是另猜一个）。
2. **检查**：查官方 registry 的 latest，与**本机版本按 semver 比**，告诉你有没有新的。
   本机是 `0.1.5-rc.2`、官方 latest 也是 `0.1.5-rc.2` 时，它就老实说"已是最新"。
3. **下载**：把官方 `.tgz` 下到 `<userData>\kernel-update\`，
   并**用官方给的 `sha512` integrity 逐字节校验** —— 对一个字节就删掉，绝不留坏包。
4. **给你命令**（**不替你执行**）：一条 `npm install -g "<那个 .tgz>"`，
   外加**必须重跑守卫**的提醒（`npm i -g` 会冲掉 `dsh` 的 shim）。

### ⚠️ 为什么这里**没有**「一键安装内核」按钮

**装内核 = 往外壳此刻正在运行的那个目录里换代码。** 2026-09-19 出过一次真实事故：
升级内核 → 失败 → 自动回滚也失败 → **客户端完全起不来，连"纯净启动"逃生通道都失效**，
最后靠用户机器上的另一个 AI 才修好。

所以这个模块的边界是硬的，最大程度到「下载 + 校验 + 给你命令」为止，
**那条命令由你在自己的终端里敲** —— 你看得见每一步，出问题也来得及停。
这就是全局规矩里那条判据：*这条命令跑下去之后，如果用户就看不见我了，那我不该跑它。*

另外三条也照旧：**不代劳、不静默、不后台轮询**（只在你点的时候查一次）。

### 为什么升级内核不会跟外壳冲突（三条，都能自己查）

| # | 机制 | 怎么自己查 |
|---|---|---|
| ① | **安装包里根本没有内核** —— 只打外壳自己的 `src/**` + `assets/**` | `npm run verify:asar` 会判定 `resources\plugins` 不存在、asar 里没有 `plugin/` |
| ② | 外壳把内核当**外部程序**：只 `spawn` 它的 `lib/bin.js` 并读 stdout，**不引用它任何内部模块** | `src/kernel.js` 的铁律 1（外壳不拥有内核） |
| ③ | 内核启动时重建的是 **`profiles\node_modules`** 这一层，而我们的插件落在 **`profiles\<档案>\node_modules`**（且是指向仓库的联接）—— **另一层** | 直接去 `$DSH_HOME` 下看，两层是不同的目录 |

⇒ 升内核不会覆盖外壳代码，升外壳也不会动内核；两边的版本可以各走各的。
**本版把这件事从"设计意图"变成了"可机械验证的断言"**（见下面验收第 ④ 段）。

## 三、安全边界：新增通道的闸门

侧栏「真打开」给了页面一个"打开本机文件"的能力，所以边界必须说清楚。
**三条缺一条，它就变成"任意网页都能启动你电脑上的程序"**：

| # | 闸门 | 怎么判 |
|---|---|---|
| ① | **来源** | 只有**主窗口、且当前显示的正是本机内核界面**才能调。★ 两个外部网站页（DeepSeek 网页版 / 开放平台）**共用同一份 preload**，那个函数在它们那儿**也存在** —— 光靠"有没有 preload"判来源会被第三方页面白拿 |
| ② | **路径** | 必须落在**你已注册的工作区**里（读 `workspace.json`），并用 `realpath` **解析联接之后**再判（`plugin/` 下有联接指向别的工作区）。越界一律拒绝并记日志 |
| ③ | **动作** | 只认 `open` / `reveal`，别的一律归一成 `open` |

**内核那几条通道**则**只放行外壳自有页面**（设置页）：官方 UI 与两个外部站点调它
一律被拒（验收里有一条专门从官方 UI 那一侧试，必须 `DENIED`）。
**下载那一步只认「检查」时主进程自己查到的那个地址** ——
渲染进程递进来的任意 URL 一律拒，否则就成了"从任意地址下任意文件"的通道。

**所有动作全是只读**：不写文件、不删文件、不改任何东西
（内核那块唯一的写，是把官方包下到它自己的 `kernel-update\` 目录）。

## 四、验收（真跑，不看脚本自述）

新增两个：

- **`node scripts/ui-check.js files`**（**21 项断言**）
  自己造一个能自证的工作区夹具（1 个子目录 + 3 个文件 + 1 个真会话），起临时内核真跑：
  **真鼠标事件**移上去（`el.click()` 不产生 `mouseover`，验不出"移上去才出现"）；
  **真点**图标，然后回读**注入脚本自己的状态** ＋ **主进程的 `shell.log`**
  —— 两份**互相独立**的证据都对上才算通；再拿"工作区外的真实文件 / `..` 穿越 / 空路径"
  各打一遍，越界必须被拒且日志留痕。
  **结果：连跑 4 次全过。**
- **`npm run kernel:check`**（**30 项断言**，真跑官方渠道）
  ① **版本比较这把尺子**（14 条，含 `rc.10 > rc.9`、`0.1.10 > 0.1.9` 两条**按字符串比会得出反结论**的）；
  ② **真连一次 npm registry**，并核对返回里**确实有可校验的 `dist`**；
  ③ **校验函数真的会拒绝坏数据**（造一个**改了一个字节**的文件喂它，必须拒绝）；
  ④ **"不冲突"那三条**机械核一遍（含 `vendor/dsh` 不存在、`extraResources` 已删）。

**结果：30/30 全过**，且 `pages` / `plugins` / `firstrun` / `loading` / `inject`
五个既有模式同时复跑，**无回归**。

## 五、这一版**没有**改什么

- **不改内核任何文件**（这条从第一版起没破过）。
- **不动 A 环境**（`%USERPROFILE%\.dsh`，只读保底家）。
- **不放松任何安全边界**：新通道按上面那些闸门把关，一处都没省。
- **不改单击的行为** —— 侧栏里读文件照旧，一个字节没动。
- **不替用户装内核** —— 那条命令交给你自己。
