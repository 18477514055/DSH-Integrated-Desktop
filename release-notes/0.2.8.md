# DSH 集成桌面端 0.2.8

把官方 DeepSeek Harness 内核装进原生 Electron 外壳。**外壳不修改内核的任何文件**；
内核由外部独立安装与升级 —— 升级内核不需要动外壳。

> 这一版做的是**分发**：**不再只依赖 GitHub**，并且**断网也能装插件**。
> 起因是用户的两句话：
> 「能不能把你的整个资源打包成一个网盘分享的压缩包形式？我们最好做一个像这样的
>   国内分发方法，**不能完全依赖 github**。」
> 「在连接不上仓库的情况下，也要检查一下本地，这样的话，别人可以从网盘中把我的插件
>   下载下来，然后在集成版插件中把它安装上去。」

> ⚠️ **必须重装一次**（不是"重启客户端"）：外壳代码是打进安装目录的，重启不会换代码。

## 一、离线装插件：新增第三个来源「本地插件包」

以前断网时是什么样：**插件清单有缓存兜底**（列表还看得见），但**装不了** ——
安装那一步只认网络下载地址，必然要走 GitHub。

现在多了一条路。把网盘包里那个 `插件包` 文件夹放到下面任一位置，客户端就能**离线**装它：

- 下载夹里的 `plugin-pack\`（或 `DSH-集成桌面端-<版本>\插件包\`）
- 桌面上的同名文件夹
- 应用数据目录里的 `plugin-pack\`
- 或者哪都不用放：**设置 → 集成版插件 → 「选择插件包目录…」**指给它

然后「设置 → 集成版插件」里多了一栏 **本地插件包**：显示找到了什么、在哪个目录、
每个包多大，点「从插件包装」即可。**首次安装向导也会自动把插件包里的条目列出来**，
断网时它会明说"改用本机插件包"。

**安全边界没有放松**（一处都没有）：

- 渲染进程**递不进路径** —— 包目录只有两种来路：主进程自己扫候选位置，
  或你在**原生目录选择框**里点出来的。界面只能递**包名**。
- 每个 `.tgz` 照旧要过 **sha256 核对 + 插件目录校验**，本地文件**不跳过任何一道**。
- 装之前**再算一次** sha256 ⇒ 关掉"扫完到装之间文件被换掉"那个窗口。

## 二、修掉一个 UX bug：「检查插件更新」不该越点越差

原来的逻辑是 `cached && !force` —— 于是有个很坑的后果：你看着好好的清单，
点一下「检查插件更新」（本来只是想看看有没有新版本），**如果那一刻断网**，
列表会整个变成「拿不到插件清单」，连"断网时还能看到上一份"这条兜底都被自己的按钮关掉了。

现在 `force` 只表示"**别用过期快照、去网上再要一次**"，不再表示"不许退回缓存"。
退回缓存时照旧如实标注「这次没连上插件仓库，显示的是缓存（时间）」——
**主动检查不该比不检查结果更差。**

## 三、国内网盘分发包（一条命令重出）

新增 `npm run pack:netdisk`（加 `--portable` 则连便携版一起，`npm run pack:netdisk:full`）。
产出：

```
DSH-集成桌面端-<版本>/
  00-先看我.md        给拿到包的人看的说明（怎么装、怎么离线装插件、怎么校验）
  安装包/*.exe        安装版（--portable 再加免安装版）
  插件包/             plugin-index.json + plugins/*.tgz
  校验/SHA256SUMS.txt 包内每个文件的 sha256
```

那个 `插件包\` 就是上面第一节认的形状 —— **同一份东西，两处用**。

索引格式与仓库里那份**同源**（同一个 `dsh-plugin-index/v1`），所以生产端加字段两边自动跟上，
不会分叉成两套。插件 tgz 用 `npm pack` **现打**（不从归档目录捞 —— 那里可能正是改了一半的那一版）。

## 四、插件改名：让开被占用的名字

查公开生态时发现两个插件的名字**已经被别人占用**：

| 原名 | npm 上是谁的 | 社区站同名收录 |
|---|---|---|
| `dsh-mobile-remote` | **good-boy4069**，0.1.0，2026-08-16 | 12 个（都不是我们的） |
| `dsh-archive-manager` | **jasonrale**，1.1.1，2026-08-15 | 48 个（都不是我们的） |

我们自己分发本来没问题（走自己的索引 + sha256），但在公开生态里**等于没有身份**：
别人搜这个名字，看到的是别人的插件。所以：

| 旧 | 新 | 版本 |
|---|---|---|
| `dsh-mobile-remote` | **`dsh-int-mobile-remote`** | 0.3.0 → **0.4.0** |
| `dsh-archive-manager` | **`dsh-int-archive-manager`** | 0.1.0 → **0.2.0** |

（`dsh-multi-session` / `dsh-plugin-uploader` 在 npm 与社区站上都干净，**没动**。）

⚠️ **改名要重启一次客户端**：换包名要重新解析 `node_modules`，这个不能热更。
装完 0.2.8 后第一次启动，档案里的两个插件会以新名字生效，**功能一个都没少**。

> 顺带说清一件事：**上传器只发到我们自己的仓库**，和 DSH 官方没有关系。
> 官方内核里**没有**"插件市场 / 上传"这个概念（`dsh plugin` 是个纯 pnpm 转发器），
> 官方文档给的只有三条**安装**来源。那个 9000+ 插件的 `dsh-plugin.org` 是**社区站**，
> 非官方，靠 GitHub topic `dsh-plugin` 发现插件。

## 五、给接手的对话留了交接文档

每个插件目录里加了一份「改名与交接」文档，写明改了什么、**为什么某些东西刻意没改**
（比如目录名 —— 仓库里的 `plugin\<目录>` 是指向第三工作区的**目录联接**，
`link:` 与联接都是写死的绝对路径，改它当场弄坏插件），以及踩过的坑。
两份 README 顶部也加了指路。

## 六、验收（真跑，不看脚本自述）

- **离线安装**：拿 `pack:netdisk` 生成的**真包**喂给外壳的消费端，三种摆法（直接指包根 /
  指解压出的最外层 / 模拟下载夹）**全部认到 3 个包**，sha256 全部通过；
  负例：把 tgz 改一个字节 ⇒ **拒绝安装**。
- **插件改名**：`dsh --profile web --dump-config` **退出码 0**，层标签已是
  `dsh-int-mobile-remote` / `dsh-int-archive-manager`，全文不再出现旧包名。
- **端到端**：`plugin-check`（多会话）与 `plugin-check-mobile-remote`（手机遥控）
  **全部 PASS** —— 后者含"配对码 → 局域网 HTTP → 新建会话/切模型/发图 →
  **去磁盘上找到提示词与图片字节**"。
- `provision:check` **63 OK / 0 FAIL**；`plugin-catalog-check` **89 OK / 0 FAIL**
  （后者拿**线上真索引**跑）。
- 插件重发三条都带**回下载重算 sha256**；索引从 9 条清到 7 条，旧名条目已摘除。

## 七、这一版**没有**改什么

- **不改内核任何文件**（这条从第一版起没破过）。
- **不动 A 环境**（`%USERPROFILE%\.dsh`，只读保底家）。
- **不放松插件的安全边界**：仍然只从我们自己的仓库（或你指定的本地插件包）装，
  仍然逐个核对 sha256。
- **不删**任何已发布的插件 Release（旧名的 Release 还在，只是不再列进索引）。
