# DSH 集成桌面端 0.2.10

把官方 DeepSeek Harness 内核装进原生 Electron 外壳。**外壳不修改内核的任何文件**；
内核由外部独立安装与升级 —— 升级内核不需要动外壳。

> 这一版就一件事：**退出要能退干净**。
> 用户原话：「先修复一个东西。我现在无法彻底退出dsh，从托盘退出也不行」
> —— 一个内核被留在端口上活着，而外壳从此再也关不掉它。

> ⚠️ **必须重装一次**（不是"重启客户端"）：外壳代码是打进安装目录的，重启不会换代码。

## 一、症状：不是"退不掉"，是**退不干净**

外壳确实退出了（窗口关掉、托盘图标消失）。留下的是**它复用的那个内核**：

| 观测 | 值 |
|---|---|
| 3105 端口持有者 | pid 9724 |
| 它是什么 | 内核：`DSH Integrated.exe --expose-internals …\@deepseek-ai\dsh\lib\bin.js web --port 3105` |
| 它的父进程 | 12160 —— **已经不在了** |
| 它的启动日志 | **不存在** |
| `kernel.json` | **不存在** |

内核占着端口、会话还活着 ⇒ **下次启动又把它复用回来**：同一个会话、同一个状态，
看起来就像"根本没退"；任务管理器里 `DSH Integrated.exe` 也还在
（内核用的就是同一个 exe —— `spawnKernel` 拿 `process.execPath` 配
`ELECTRON_RUN_AS_NODE=1` 当 node 用）。

## 二、根因：一条走不回去的单向门

```js
serverOwned = false;                            // ① 复用 = 只承认"不是我起的"
if (kernelProc && serverOwned) killTree();       // ② 退出时只关"我 spawn 的那个"
stopOwnedKernel(); ensureServer({reuse:false})   // ③ 重启内核 ⇒ 端口被占 ⇒ 永远失败
```

一旦走到「复用」，`serverOwned` 永远是 false ⇒ **那个内核永远没人关**；
而你想手动救回来也不行：「重启内核」要先停掉端口上的内核，可它恰恰是外壳不敢停的那个
—— 现场连点三次，报的都是 `端口 3105 已被占用，但上面探测到的不是 dsh 服务`，
**而这句话本身就是错的**（探活明明认出上面就是 dsh）。

还有一条暗线：`kernel.json` 是被 `stopOwnedKernel()` **无条件**清掉的 ——
它什么都没杀，却把记录抹了 ⇒ 此后永远退回裸 origin、永远认不出那个内核是自己人。
**这就是单向门的起点。**

## 三、修法：**能证明才认领**

原则一句话：**能证明"这个内核是本应用拉起来的"，就认领它、退出时关掉它；
证明不了（例如你自己在终端里 `dsh web` 起的），一个字都不动。**

| 环节 | 做法 |
|---|---|
| **判据** | 四条**只含 ASCII** 的判据：可执行文件名 = 本外壳 + `--expose-internals` + `lib/bin.js` + 同一个端口 |
| **认领** | 复用（带记录 / 裸 origin 两条路）时都要过一遍判据；**父进程还活着就不认领**（那是另一个外壳实例在用的内核） |
| **收尾** | 退出时关"自己 spawn 的 + 认领来的"；托盘「退出」、安装包退出、验收脚本**走同一个 `quitApp()`** |
| **拆单向门** | 「重启内核」能停认领来的内核；记录只在**真动了那个 pid** 时才清；停完**等端口放开**再起新的 |
| **说真话** | 端口占用时**先探活再下结论**：上面是 dsh 就照实说，不再把"已经在跑的 dsh"误报成"别的程序占端口" |
| **看得见** | 托盘「关于」多一行 **`内核归属`**：本应用启动 / 认领来的 pid / **不是本应用启动的（退出时不动它）** |

★ 用户现场那个内核（pid 9724）的命令行**四条判据逐条命中**，父进程已不在
⇒ 装上新版本后它会**被认领**，退出时一起关掉。
而你（或任何程序）自己起的那个 —— 命令行是 `node.exe`，第一条就不命中 ⇒ **一个字节都不动**。

## 四、新增验收：`npm run quit:check`

退出这条路以前**一条断言都没有**（`npm run` 里根本没这项），所以它坏了几天没人发现。

```powershell
npm.cmd run quit:check                      # 两个现场都跑（约 3 分钟）
node scripts/quit-check.js --mode=norecord  # 只跑用户现场
```

真跑，全程临时 userData + 临时 DSH_HOME，**不碰你的环境、不碰 3105**。
两个现场：**记录还在**（走带记录复用）与**记录丢了**（走裸 origin 复用 —— 用户现场）。
断言 13 条 × 2 = **26 条**，修复前 `21 PASS / 3 FAIL`，修复后 **26 PASS / 0 FAIL（连跑 4 次）**。

★ 「孤儿内核」这个现场**不能靠"强杀外壳"复现** —— 实测外壳一死内核也跟着死
（job 对象），所以由 `scripts/quit-orphan.js` 用一个一次性父进程以 `detached` 起内核、
拿到就绪信号后自己走人，造出"父进程已死、却还在服务"的内核。

## 五、验收（真跑，不看自述）

| 检查 | 结果 |
|---|---|
| `npm run quit:check` ×4 | **26 PASS / 0 FAIL**，四次一致 |
| `node scripts/ui-check.js reuse` | **7/7 PASS**（含「外壳退出后**外来内核依然活着**」⇒ 别人的内核没被动） |
| `node scripts/ui-check.js loading` | 2 FAIL —— **与上一版逐条一致**（既有竞态，非本版引入，已 A/B 核对） |
| `npm run kernel:check` | 全 PASS（外壳仍把内核当外部程序 / 安装包不含内核 / 三条不冲突不变量） |

## 六、给自己人的两条警告

1. **别在会话里跑 `npm run smoke`**：它用**真实 userData**，会认领到你此刻正在用的内核，
   而冒烟收尾会把它关掉 —— 等于把正在跑的客户端弄停。已加闸：
   `finishSmoke()` 走 `shutdownKernels({ adopted: false })`，**自检只关自己 spawn 的那个**。
   同理：任何开发态 `electron .` 都必须带 `--user-data-dir=<临时目录>`。
2. **跨 PowerShell 边界的字符串判据，不要依赖非 ASCII 内容**：WMI 的 `CommandLine`
   经 PowerShell 往返后中文段会被改掉，第一版修复就是因此**完全无效**（判据永远为假）。
