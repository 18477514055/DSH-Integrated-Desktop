# DSH 集成桌面端 0.2.15

**用户问「检查内核更新可靠吗？不是已经跑到 0.1.7 了吗」——
查出来的结论有两层：一层是它只问了 npm 的一个标签，另一层是 0.1.7 在外壳上根本起不来。**

> 用户原话：「话说你这个检查内核更新的功能可靠吗？我现在只检测到了一个 0.1.5 的一个小版本，
> 但是现在不是已经跑到 0.1.7 了吗？」

---

## 一、先回答原问题：**功能没撒谎，是信息来源选窄了**

直连 `registry.npmjs.org` 实测（不经外壳、不经代理工具）：

```
dist-tags = { latest: "0.1.5-rc.3", next: "0.1.7-rc.2", alpha: "0.1.7-alpha.2" }

0.1.7-rc.2   2026-09-24T14:18Z      ← 确实存在，而且更新
0.1.5-rc.3   2026-09-22T05:55Z
```

旧代码（`src/kernel-update.js`）查的是 `…/@deepseek-ai/dsh/latest`，读 `meta.version`。
按 `latest` 标签算，「官方最新 = 0.1.5-rc.3」这句是**真的**——
**没有缓存坏、没有代理坏、没有拿错包。** 错的是它**只问了那一个标签**，
于是把"正式渠道推荐的那版"说成"官方最新"，0.1.7 整个看不见。

⇒ 现在改成读**整份元数据**（npm 精简格式，实测 ~145 KB，`dist-tags` 与每个版本的
`dist` 一个不少），把**全部发行渠道都列出来**。

### 三条口径写死在界面上

| | 说明 |
|---|---|
| **默认渠道仍是 `latest`** | 不替用户把预览渠道当默认 |
| **`npm i -g @deepseek-ai/dsh` 只装 `latest`** | 所以命令行**装不到** 0.1.7。要装别的渠道只能用下载下来的那个 `.tgz`（版本钉在文件名上） |
| **全部渠道里最高的那版，官方没提升它** | 界面写明「它不在正式渠道上」—— 这是事实，不是我们的判断 |

## 二、★★ 真正的答案在第二层：**0.1.7 在外壳上起不来**

渠道清单做出来之后立刻浮出一个更要紧的问题：**这些版本真的能跑吗？**
本项目 `$DSH_HOME/AGENTS.md` 第二条铁律写着「验证'某东西能否工作'必须**真让它工作**」——
所以没有推断，全部真跑（新工具 `scripts/kernel-compat-check.js`，每条都是一次真启动）：

| 内核版本 | 渠道 | 结果 |
|---|---|---|
| `0.1.5-rc.2` | （本机在用） | ✅ 就绪 |
| **`0.1.5-rc.3`** | **`latest`（正式渠道）** | ✅ **就绪** |
| **`0.1.7-rc.2`** | **`next`（预览渠道）** | ❌ **`Unsupported/no-context`** |
| `0.1.7-alpha.2` | `alpha` | ❌ 同上 |
| `0.1.7-rc.2` | 改用**系统 node 24** 跑（对照） | ✅ 就绪 |

最后一行是对照实验，它把病因锁死了：**卡的是 Electron，不是内核本身。**

### 内核自己打出来的原文

```
dsh: fatal uncaught exception: Error: dsh: host preparation failed:
node-addon-require-builtin unsupported: Unsupported/no-context
(unsupported Electron runtime fingerprint: Node 22.21.1,
 V8 13.8.258.32-electron.0 (supported Electron versions: 43.0.0, 44.0.0, 45.0.0-alpha.6))
```

表现是加载页**永远停在「正在等待内核就绪…」**，日志里只有这一行 fatal。

### 机制（逐文件数出来的，不是猜的）

| 内核 | `dsh-app-boot/lib/index.js` 里 `installRuntimeInterception` |
|---|---|
| `0.1.5-rc.3` | **0 处**（根本没有这个调用） |
| `0.1.7-rc.2` | **3 处**（`requireBuiltin` 相关 5 处） |

⇒ **`0.1.6` 起内核新增了运行时拦截**：要 hook V8 内部去 `require` 内置模块，
而它依赖的 `node-addon-native-custom-loader@0.1.6` 只认 **Electron 43/44/45** 的运行时指纹。
两个内核带的是**同一个** 0.1.6 版加载器 ⇒ **差别在调用方**。
外壳带的是 **Electron 37** ⇒ 那一代内核**连启动都过不去**。

> ★ 这条结论对未来很重要：**外壳的 Electron 版本是一个硬约束**，
> 不是"随便升升就好"的实现细节。要上 0.1.6+ 的内核，先得把 Electron 提到 43+。

## 三、界面因此多了「能不能跑」这一栏

`channelsFromMeta()` 是**纯函数**，`compatOf(version, electron)` 判四档，
**证据等级写在脸上**：

| 等级 | 含义 |
|---|---|
| `verified-ok` / `verified-bad` | 这一版**真跑过**（附内核原文） |
| `gen-ok` / `gen-bad` | 没逐版跑过，**只给世代结论**并注明是推断 |

★ 绝不把"同世代"写成"实测"——那正是本项目记过两次的「拿代理证据当通过凭据」。

界面上：

* 「实测起不来」的渠道那**一行变红**，写明「要 Electron 43/44/45」；
* 说明区点破：**装了会让客户端起不来** —— 想拿文件可以下，**别装**；
* 下载区仍然允许下载（下载本身无害），但会顶一条红字：
  「下面的命令只用来把文件拿到手，等外壳换了 Electron 再装」；
* 非默认渠道的下载确认框里也会带这句警告。

## 四、★ 为什么把这件事做成纯函数（而不是"再多跑一次网络"）

用户报的那个 bug **不该靠"此刻 registry 上恰好有什么"去验** ——
上游哪天把 `latest` 提升到 0.1.7，真跑断言就自动变成"验不到"，护栏失效。

⇒ 拆出 `channelsFromMeta(meta, cur, opts)`（不联网、不读盘、不看时钟），
验收脚本喂一份**与 2026-09-25 那天完全相同**的元数据，离线且**永远可复现**地断言：

* 三个标签一个都没漏；
* `0.1.7-rc.2` 出现在结果里、且被标成「比默认渠道新」**并且**「实测起不来」；
* 默认渠道仍然是 `latest=0.1.5-rc.3`。

### 配套的「护栏的护栏」

`COMPAT_EVIDENCE` 里每条记录都钉着**验它时的 Electron 版本**。
`kernel-update-check` 有一条断言盯着这件事：**记录里的 Electron 与本机不符就 FAIL**，
逼你重新跑 `kernel-compat-check.js`。⇒ 哪天外壳升级了 Electron，这张表不会**悄悄过期**。

## 五、新增两个可复用的工具

```powershell
# ① 某一版官方内核能不能跟外壳一起跑？（真装 + 真启动，判据是"拿到本机地址"）
node scripts/kernel-compat-check.js --version=0.1.7-rc.2
node scripts/kernel-compat-check.js --version=0.1.5-rc.3 --version=0.1.7-rc.2
node scripts/kernel-compat-check.js --version=0.1.7-rc.2 --runtime=node   # 对照组
#   退出码 0=能跑 2=起不来 3=装不上 4=用法错

# ② 让**既有**的界面验收在指定版本内核上原地跑一遍
node scripts/ui-check.js loading --kernel=0.1.5-rc.3
node scripts/ui-check.js pages   --kernel=0.1.5-rc.3
```

`--kernel=<版本>` 用的是**外壳自己那条装内核的路**（`kernel-provision.js`），
装进 `<临时 userData>\kernel\<版本>\` ⇒ 发现链 **②.5 级「外壳安装」**（排在全局 npm 之前）
会优先选中它。判据落在 `shell.log` 的 `使用内核:` 与 `内核就绪:` 两行 ——
**不是"我们把它装上了"**。

★ 两个工具全程只写 `%TEMP%`：不碰用户正在用的内核、不碰全局 npm、不碰 B / A 两个 DSH 家。

## 七、边界（说清楚，别以为它比实际更强）

* **没有"自动帮用户升级内核"** —— 与 0.2.9 起的边界一致：只**下载 + 按官方 sha512 校验 + 给命令**，
  命令由用户在自己的终端里执行。理由见 `release-notes/0.2.9.md`（2026-09-19 的事故）。
* **「起不来」目前是硬编码的证据表，不是通用检测器** ——
  要判断"某一版内核能不能跑"，唯一可靠的办法是 `kernel-compat-check.js` 真跑一次。
  界面上的判定只覆盖**验过的那些版本 + 两个世代**，会说清哪条是实测、哪条是推断。
* **`0.1.7` 的文件仍然可以下载** —— 下载本身无害，而且外壳换了 Electron 之后那个包就能用。
  但界面上会明确写「别装」。
* **`kernel-provision.js` 装内核时仍然只查 `latest`** —— 那是刻意的：
  那一段的语义是"新装一个能用的内核"，装正式渠道那一版是对的；
  "看得见有哪些版本"是 `kernel-update.js` 渠道清单的事。两处都留了注释说明，别互相"顺手改"。
