# DSH 集成桌面端 0.2.18

**这一版修的是你问的那件事：「集成版插件」页面里，你装了十几个，它只显示 4 个。**
另外 0.2.17 的修复（模型胶囊"点一下整张列表消失"、多会话插件 0.1.3）**也都在这个包里**
—— 0.2.17 没有发布过，所以 **0.2.18 是第一个包含它们的、可以装的包**。

> 用户原话：「一个很离谱的事情，你那个集成板插件的界面是静态的吗，
> 我们现在安装了大量本地插件，那里还是4个。」

---

## 一、先回答"是不是静态的"：**不是静态，是它只画"仓库清单"**

那个页面显示的 4 条不是写死的，是**插件仓库的清单**（`DSH-Plugin-Hub` 的
`plugin-index.json`，本机缓存 `plugin-index-cache.json`，再与 npm 上各包的最新版合并）
—— 实测清单里是 **14 条 / 4 个不同的包**：

```
dsh-int-archive-manager 0.2.0 · dsh-int-mobile-remote 0.11.0
dsh-multi-session 0.1.1       · dsh-int-plugin-uploader 0.1.6
```

而你家里实际是（同一次实测）：

```
profiles/web/package.json 的 dependencies：16 个
dsh.profile.bundles：17 个
  dsh-connect-workbuddy / dsh-qoder-connect / dsh-crosshub / dsh-mcp-plus /
  dsh-plugin-install / dsh-whale-widget / dsh-plugin-uploader / @dsh-pet/bridge /
  dsh-int-multi-session / dsh-int-mobile-remote / dsh-int-archive-manager /
  dsh-int-im-file-inbox / dsh-int-context-cap / dsh-int-wallpaper /
  dsh-int-model-router / dsh-int-context-viewer
```

### 根因：合并函数只遍历**远端清单**（`src/plugin-catalog.js:598`）

```js
function mergeInstalled(groups, installed) {
  const byName = new Map((installed || []).map((p) => [p.name, p]));
  return groups.map((g) => { … });   // ★ 只遍历远端清单；installed 只用来"标注"
}
```

⇒ 本机装了、但**仓库清单里没有**的插件（dev 联接 / 本地 tgz / 从 npm 装的 / 别处发布的），
**一行都不会出现**。你那 16 个里绝大多数属于这一类，于是页面上永远只有 4 条。

## 二、修法

1. **新增一列 `offIndex`**（`PC.offIndexRows`）：仓库清单**之外**、本机确实装着的插件，
   照样画卡片，标成「本机装的」，并写明**本机版本 / 来路 / 落点**。
2. **计数改成说真话**：`已装 N / 仓库清单 M · 本机另有 K 个不在清单里`
   （`N` 把清单之外的也算进去 —— 它们本来就装着）。
3. **清单之外那些不编造线上信息**：不写「线上 v…」（以前会印出 `线上 vundefined`）、
   不写 sha256、也不给「安装 / 更新 / 改用仓库版」按钮（仓库里根本没有它，只给「卸载」）。
4. **说明文字改从本机 `package.json` 读**：仓库索引里我们这些条目的 `description`
   是空的（索引由插件清单生成）⇒ 界面以前整片显示「（发布者未填说明）」，看着像死的。
   现在本机装着就读本机那份（`probePackage` 顺带把 `description` 带出来）。
5. **清单取不到时也照列本机插件**（断网且没缓存）：那正是"本机有什么"最该看得见的时候。
   以前这种情况整页只有一句「拿不到插件清单」。

★ 为什么是**单独一列**而不是并进 `rows`：`rows` 还被**首启向导**当"可勾选要装的"清单用，
并进去会让"已经装着的插件"出现在向导的勾选列表里。

## 三、验收：`node scripts/ui-check.js plugins`（真跑，**全部通过**）

夹具改成两个（各自验一件不同的事）：

| 夹具 | 验什么 |
|---|---|
| `dsh-fixture-offindex`（清单里永远不可能有这个名字） | **清单之外、本机装着**的那些要有卡片（用户报的那一类） |
| 一个**用清单自己报的名字**种的 dev 联接 | 清单里的条目、本机装的是**本地来源** ⇒「已装（本地装的）」/「改用仓库版」 |

★ 原来第二个夹具把名字写死成 `dsh-multi-session`：清单改成 npm 名（`dsh-int-*`）之后，
它被**正确地**判成了"清单之外"，那两条老断言于是开始假 FAIL —— **夹具赶不上现实**。
现在改成"先渲染拿到清单报的名字，再按那个名字种"，与清单怎么命名无关。

实测输出：

```
计数: 已装 1 / 仓库清单 4 · 本机另有 1 个不在清单里   卡片数: 5
PASS  ★★ 清单之外、本机装着的插件**也有卡片**（以前它一行都不出现）
PASS  ★ 它被标成「本机装的」
PASS  ★ 它不编造线上版本（不出现「线上 v」/undefined）
PASS  它写清「仓库清单里没有它」，并报本机那一份的版本 1.2.3
PASS  它的说明读的是本机 package.json（不是「发布者未填说明」）
PASS  ★ 种上 dev 联接后「已装 N」跟着涨（不是写死的）   ← 1 → 2
PASS  每张仓库清单里的卡都标了来路（「来自 <owner/repo>」或「来自 npm」）
[ui-check] plugins 模式全部通过
```

⚠️ 安装路径那 8 条这一趟是 **SKIP**（`下载失败：net::ERR_CONNECTION_TIMED_OUT`）——
以前它们会因为网络抖动变成 8 条**假 FAIL**，现在明确标 SKIP、**不算通过**。
这是本机代理抖动的老毛病（本项目一直如此），与本版改动无关。

## 四、0.2.17 里那两件（也在这一版）

* **模型选择菜单**：点某个提供方标签后**整个下拉消失**（真 bug，根因是焦点被隐藏操作偷走
  ⇒ 官方 `onBlur` 关菜单），并把标签行样式改好。详见 `release-notes\0.2.17.md` 与
  `docs\模型胶囊点空bug-2026-09-26.md`。
* **多会话插件 `dsh-int-multi-session` 0.1.3**：内核 0.1.7 改了契约
  （`create()` 之后**必须先 retain 身份**才借得到 binding）⇒ 以前"会话建得出、消息发不出去"。
  `plugin:check` 从 3 FAIL 变 **44 PASS / 0 FAIL**（连跑 4 次）。
  ⚠️ 插件不在安装包里，要另外装/更新，且**装完必须重启一次客户端**。

## 六、这一版**没有**做的事（如实说明）

* **没有上传**：GitHub Release、网盘包、npm 上的插件包都还是旧的
  （`dsh-int-multi-session` 停在 0.1.1，`dsh-int-context-cap` 停在 0.2.1）。
* **没有改**上下文上限插件（你说那个问题已经解决了）。
* 仓库索引本身还是 **2026-09-23** 那一份：清单里那 4 个包的版本、以及我们插件的说明文字，
  要等重新生成并上传索引之后才会变新 —— 那是"上传"那一步的事。
