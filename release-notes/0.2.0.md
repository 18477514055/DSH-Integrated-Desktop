# DSH 集成桌面端 0.2.0

把官方 DeepSeek Harness 内核装进原生 Electron 外壳。**外壳不修改内核的任何文件**，
内核由外部独立安装与升级 —— 升级内核不需要动外壳。

## 这一版做了什么

### 1. 图标：白底 + 黑鲸鱼

形状取自官方 `favicon.svg` 的鲸鱼路径（不是自己画的），生成：

| 文件 | 用在哪 |
|---|---|
| `icon.ico`（16/24/32/48/64/128/256 多尺寸） | **exe 文件图标 + 桌面/开始菜单快捷方式 + 安装器** |
| `icon.png` 512 / `icon-256.png` | 窗口图标 |
| `tray.png` 32 / `tray@2x.png` 64 | 托盘（高分屏自动选用 @2x） |

原来用的是社区版遗留的占位图（**白色图形 + 透明底**），在浅色任务栏上几乎看不见。

### 2. 启动加载页 + 诊断与修复

- 白底 + 大黑鲸鱼 + 进度条与阶段清单
- **进度条只走真实里程碑**（读取配置 12% → 查找内核 30% → 启动内核 52% → 等待就绪 78% → 100%），
  里程碑之间只有一道流光表示"在干活"，**数字不动** —— 内核不汇报启动进度，
  做一条匀速爬升的假进度条就是在向用户谎报状态
- 底部「诊断与修复」上拉抽屉，8 条动作 + 流式输出：
  重启内核 / 纯净启动 / 退出纯净模式 / 浏览器启动 / 环境体检 /
  打开 DSH_HOME / 打开日志目录 / 复制诊断信息 / 切到保底客户端
- 独立的**设置页**（托盘右键、`Ctrl+,`、加载页按钮），分「常规 / 诊断与修复 / 关于」，
  与加载页抽屉**共用同一份动作白名单**

安全设计：渲染进程**永远拿不到命令字符串**，只能提交动作 id；主进程再验来源
（看 frame 真实提交的 URL）；具体做什么写死在白名单里。会打断用户的操作只提供按钮。

### 3. 模型选择器：搜索框 + 提供方胶囊

输入框下方那个「选择模型」菜单里加搜索框与提供方筛选。

做法是**运行时注入**，只用官方的语义属性（`div[role="menu"]` /
`section[role="group"][aria-labelledby]` / `button[role="menuitemradio"]`），
**一个哈希类名都不碰**，**不改内核任何文件**；万一官方改版，退化结果只是"没有搜索框"。

> 说明：官方版本本身已经按提供方分组了，本项目补的是**搜索框**与**提供方筛选胶囊**。

### 4. 修了 3 个实测暴露出来的 bug

| bug | 症状 |
|---|---|
| 复用已有内核时把 401 地址当成可加载地址 | 端口上有别人起的 dsh 时，界面只显示一行英文 401 |
| `showStatus` 在导航成功前就把状态置成"已在状态页" | 一次导航失败就让界面卡在中间态 |
| IPC 来源判据用"意图标志"而非"屏幕上事实" | 页面报「拒绝：当前显示的不是外壳自有页面」 |

## 验证方式

都是**真跑真看**，不是"文件存在"：

```
node scripts/ui-check.js loading   # 加载页 + 抽屉 + 动作清单（含真跑一次环境体检）   14/14
node scripts/ui-check.js inject    # 模型搜索框：真点开菜单、真在输入框里打字        14/14
node scripts/ui-check.js reuse     # 复用内核的两条路径（记录可用 / 记录不可用）      8/8
npm run verify:icon                # 图标逐像素：白底、不透明、黑鲸鱼、居中、镂空、ICO 尺寸
```

四个模式都**不碰**你正在用的环境（临时 userData + 空闲端口；`reuse` 自己起一个"外来内核"造场景）。

## 安装须知

1. **先退出正在运行的旧版本**（托盘右键 → 退出；点右上角 X 只是最小化到托盘）。
   本应用是单实例的，旧版还开着的时候启动新版会**直接退出并聚焦旧窗口**，看起来像"双击没反应"。
2. 装完如果桌面图标还是旧的，那是 **Windows 图标缓存**，不是没装上：
   `ie4uinit.exe -show`，或重启一次资源管理器。
3. 需要本机已安装官方内核：`npm i -g @deepseek-ai/dsh`。
