# DSH 集成桌面端 0.2.6

把官方 DeepSeek Harness 内核装进原生 Electron 外壳。**外壳不修改内核的任何文件**；
内核由外部独立安装与升级 —— 升级内核不需要动外壳。

> 这一版兑现 0.2.5 结尾那句承诺：**首启勾选向导**与**摘掉随包内置插件**同版本落地。
> 用户原话：「我们发出去的包干干净净的，有本体客户端就足够了……如果他们在下载的时候
> 或者安装的时候勾选，他们就从我的仓库的其他链接拉取他们。」

## 一、包**干干净净**了：安装包不再带插件

`package.json` 里那条把插件塞进产物的 `extraResources`
（`runtime/materialized-plugins` → `resources\plugins`）**已经删掉**，
`pack` / `dist` / `dist:portable` 里那一步 `materialize-plugins` 也一并去掉。

于是安装目录只剩**本体客户端**：

```
resources\app.asar        ← 外壳自己的代码
resources\plugins\        ← ★ 这个目录不再存在
```

**为什么必须和向导一起发**：单摘掉插件会让新用户装完是一个**空客户端**
（界面在、插件一个没有，还得自己会 pnpm、会改 profile）。两件事是同一个改动。

**已经装过的用户不会掉插件。** `src/plugins.js` 的 `provision()` 在"来源目录不存在"时
是 `ok=true` 的**空转**（`src/plugins.js:289-293, 370-374`），它**不会**去删你家里已有的东西。
你 `<DSH_HOME>\plugins\` 下的副本、profile 里那三处契约，一个字节都不动。

> 这一条由机械断言盯着：`npm run verify:asar` 现在会**判定**
> `resources\plugins` 是否存在、`app.asar` 里有没有 `plugin/` ——
> 谁把 `extraResources` 加回来，命令当场 FAIL。

## 二、首启向导：一屏勾选，从仓库拉

全新安装第一次启动，**内核就绪之后**会自己弹出一个窗口（标题是「欢迎使用 · DSH 集成桌面端」，
不是「设置」），里面是插件仓库的清单，每条一个勾选框：

| 行为 | 说明 |
|---|---|
| 默认勾选 | **能装的、且不是开发者工具**的那些。开发者工具（`dsh-plugin-uploader`）默认**不勾** |
| 勾不动 | 已经装好的、不适用于本外壳的，画成灰的并且**点不动**（不给"看着能点其实点不动"的按钮） |
| 计数 | 按钮文案跟着勾选数走：「安装选中的 3 个插件」；一条都不勾就**变灰** |
| 安装 | 真去仓库下载、逐个核对 `sha256`、装进 `<DSH_HOME>\plugins\` 并写 profile 三处契约 |
| 装完 | 出现收工块：装了什么、哪些失败了（连原因）、**下一步点「重启内核使其生效」** |
| 不想挑 | 「先跳过，直接开始用」—— 记一笔账，然后**把窗口让开**，露出客户端本体 |

**只对全新用户弹。** 判定是三条同时成立（`main.js` 的 `firstRunDue()`）：

1. 这一份 userData 没走过向导（`<userData>\first-run.json` 里没有 `done:true`）；
2. 不是开发机（默认只在打包版自动弹，理由见下）；
3. **这个家里一个插件都没有** —— 所以从 0.2.5 升上来的老用户**根本不会看到这个窗口**，
   他们的插件本来就是装好的。这条判据**只看本机磁盘、不联网**。

**老用户想装新插件怎么办**：「集成版插件」栏里多了一行
「**第一次装插件** → 打开首次安装向导」，随时能回去。

**开发机默认不弹**的第二条理由很实在：本项目的验收脚本全都用一个全新的临时
`--user-data-dir` 起真客户端 —— 如果开发模式也自动弹，六个模式每个都会多出一个设置窗口、
多一个 CDP page 目标，把它们的判据全搅乱。要主动验它用 `DSH_FIRST_RUN=force`；
用户想关掉它用 `DSH_FIRST_RUN=off`（不必等我们发新版本）。

**这个窗口从来不阻塞启动**：它是一个独立窗口，主界面照常在后面加载完。

## 三、顺手修掉的两个真 bug（都是被这一版踩出来的）

**① 托盘那条「检查更新…」其实一直没生效。**
主进程是在设置页 `did-finish-load` 那一刻把"跳到更新栏"推过去的，
而页面要 `await getEnv()` 之后才订阅那个通道 —— 两个时刻谁先谁后没有保证，
实测**那条消息丢了**：窗口打开了，但停在「常规」栏、也不会自动查一次。
现在订阅提前到**同步执行期**，先记下来、接线好了再执行。
（首启向导走的是**同一条路** ⇒ 不修的话向导会停在「常规」栏，用户根本看不到勾选清单。）

**② 设置页里有四处字面的 `**`。**
那是 markdown 的强调写法，而 HTML **不解析 markdown** —— 界面上就是四个星号
（「查到就能\*\*直接下载并安装\*\*」）。已改成 `<b>`。

## 四、装完之后要重启一次内核

插件是内核启动时读 profile 决定的。向导装完会直接给一个「重启内核使其生效」按钮 ——
它走的是**诊断白名单里那一个** `restart-kernel`（与「诊断与修复」栏同一个动作，
包含"换档案起不来就退回原档案"的失败回退），**不另写一套重启逻辑**；
点之前会先确认（重启会打断正在生成的回答）。

「集成版插件」栏里单个装/更/卸之后，仍然是那句话：**重启一次客户端才生效**。

## 五、验证方式（真跑，不看自述）

新增 `node scripts/ui-check.js firstrun` —— **两次真启动**，用**同一个**临时 userData：

```
第一趟（全新家）
  ★ 全程不点任何东西，向导自己弹出来
  ★ 窗口标题是「欢迎使用…」（窗口标题从应用日志回读 —— CDP 只看得到文档标题）
  ★ 停在勾选那一栏，且这一栏**不在**左侧导航里
  ★ 清单真渲染出来了；至少一条默认勾上；开发者工具默认不勾
  ★ 一条都不勾时安装按钮变灰、文案回到默认
  ★「先跳过」把标记写成 {done:true, skipped:true}，并且真的关掉了窗口
  ★ 跳过之后家里依然零插件（跳过就是跳过）
第二趟（同一个家、依然零插件 ⇒ 唯一拦住它的是那个标记）
  ★★ 不再自动弹
  ★ 从「集成版插件」栏手动打开向导，按钮点了真的切到那一栏
  ★ 真装一个（只勾一条）→ 收工块出现且说清要重启
  ★ 磁盘核对：<DSH_HOME>\plugins\<名字>\package.json 在、
    ① dependencies 是 link: 指向它 ② bundles 含它 ③ node_modules 联接解析到它
  ★ 标记更新成 installed:[那一个]
```

`npm run verify:asar` 增加 `src/first-run.js` 与首启向导的功能标记，
并把「干净包」从"打印一句"升级成**断言**（见第一节）。

## 六、这一版**没有**改什么

- **内核一个字节没动**，外壳仍然零运行时依赖（`first-run.js` 只用 `node:fs` / `node:path`）。
- **没有做**插件版本历史 / 回滚到旧版本（那是插件上传器的能力，用户侧暂不需要）。
- **没有做**托盘里的「检查插件更新…」菜单项（向导与设置页两条路已经够用）。
- `scripts/materialize-plugins.js` 与 `src/plugins.js` 的物化/落位能力**保留**：
  它不再参与打包，但仍是"万一以后要恢复随包分发"的那条路，且 `npm run provision:check`
  一直在验它。
