# DSH 集成桌面端 0.2.2

把官方 DeepSeek Harness 内核装进原生 Electron 外壳。**外壳不修改内核的任何文件**，
内核由外部独立安装与升级 —— 升级内核不需要动外壳。

> **这一版只做一件事，但它是"能不能发给别人用"的分水岭：插件现在内置了。**
> 装完打开客户端，插件就已经在里面 —— **不再需要任何人敲命令**。

## 这一版解决了什么

### 0.2.1 的实际问题：包里有插件，但别人装了等于没有

0.2.1 把插件打进了安装包，可是把它接进 DSH 环境的那一步，写进 profile 的是：

```
"dsh-multi-session": "link:D:\deepseek-workspace\5.DSH集成桌面端\plugin\dsh-multi-session"
```

那是**开发机上的绝对路径**。而且插件本身被打在 `app.asar` 里 ——
别人机器上既没有那个 workspace，asar 里的目录也不是能被联接的真实路径。
⇒ **对方装完，界面上什么插件都没有**，还得自己会 pnpm / 会改 profile / 会建目录联接。
对"接收方"来说，这等于没有。

### 现在的做法：随包分发 → 首次启动自动落位

1. **插件作为真实目录随包分发**：electron-builder 的 `extraResources` 把
   `plugin/` 放到 `<安装目录>\resources\plugins\`（不再塞进 `app.asar`）。
2. **外壳启动时自动"内置"进 profile**（新模块 `src/plugins.js`），落在

   ```
   %APPDATA%\DSH Integrated\dsh-home\plugins\<插件名>\
   ```

   并把 profile 的三处契约一次写对：

   | # | 写哪儿 | 写成什么 |
   |---|---|---|
   | ① | `profiles/web/package.json` → `dependencies` | `"link:<DSH_HOME>\plugins\<插件名>"` |
   | ② | `profiles/web/package.json` → `dsh.profile.bundles` | 追加插件名 |
   | ③ | `profiles/web/node_modules\<插件名>` | 目录联接 → 上面那个目录 |

   （漏任何一处都是"文件都在、界面什么都没有" —— 这是本项目踩过的老坑。）

3. **与应用安装目录彻底解耦**：`link:` 指向**用户数据目录**下的副本，不是安装目录。
   ⇒ 应用升级/卸载都不会让插件变成死链。
4. **全新机器会多一次内核重启**：profile 是内核第一次跑起来才创建的，
   所以要"起内核 → 装插件 → 重启一次内核让它重读 profile"。
   用户只会看到加载页多停一两秒，**不需要做任何操作**。
   已经装过的机器走"先装好再起内核"这条路，**零重启、零感知**。

### 顺带：不再把 Gradle 构建产物打进安装包

`plugin/dsh-mobile-remote/android/` 里有 `.gradle` 缓存与 `build/` 中间件
（约 **4.1 MB**，其中还有 **232 字符深度**的路径，超过 Windows 260 的经典上限，
复制时有真实风险）。这些对插件运行毫无用处，已从分发内容里排除。

## 开发机不受影响

内置逻辑**只在打包版默认开启**。开发机上跑 `npm start` 时它默认不动，
免得把 `install-plugin.js` 建的开发用联接（→ 仓库目录，改源码即时生效）悄悄改写掉。

想验证打包行为可以在开发机上强制打开：

```powershell
$env:DSH_BUNDLED_PLUGINS="auto"; npm start
```

## 验证方式（真跑，不看自述）

```
npm run provision:check     # ★ 本版新增：内置插件逻辑的真跑验收，40 条断言
npm run plugin:check        # 插件本身的功能验收（搭临时环境真启动、真发消息）
npm run release:check       # 分发暂存区逐文件机械审计
```

`provision:check` 在**临时 DSH_HOME** 上真的建 profile、真的调落位逻辑，
然后去磁盘上找插件字节与联接指向。它覆盖：

- 全新机器（profile 还不存在）→ 报 `profile-missing`，不抛错、不乱写；
- 三处契约全部落位，且**联接里真能读到** `lib/client.js`；
- **幂等**：紧接着再跑一次，`changed` 必须为空；
- **不越界**：别人的依赖条目、别人的 bundles 条目、别人的 `node_modules` 真实目录一个不动；
- **自愈**：插件副本被改坏 / 联接被删 → 下一轮自动修复；
- `_retired` 这类下划线目录不被当成可分发的插件；
- **打包形态**（srcRoot 换成模拟的 `resources/plugins`）行为一致。

## 安装须知

1. **先退出正在运行的旧版本**（托盘右键 → 退出；点右上角 X 只是最小化到托盘）。
   本应用是单实例的，旧版还开着的时候启动新版会**直接退出并聚焦旧窗口**，看起来像"双击没反应"。
2. 装完如果桌面图标还是旧的，那是 **Windows 图标缓存**，不是没装上：
   `ie4uinit.exe -show`，或重启一次资源管理器。
3. 需要本机已安装官方内核：`npm i -g @deepseek-ai/dsh`。
4. **插件不用再单独装了** —— 打开客户端就有。
   首次启动若在"正在装载内置插件…"多停一下，那是一次性的。
