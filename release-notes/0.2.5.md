# DSH 集成桌面端 0.2.5

把官方 DeepSeek Harness 内核装进原生 Electron 外壳。**外壳不修改内核的任何文件**；
内核由外部独立安装与升级 —— 升级内核不需要动外壳。

> 这一版是**插件管理器**的第一半：外壳设置里多了一栏「集成版插件」，
> 能看清单、点「检查插件更新」、直接装 / 更新 / 卸载。
> **首启勾选向导**与**摘掉随包内置插件**放在 0.2.6 —— 两件必须同版本发，
> 否则新用户装完会是一个空客户端。

## 一、设置页多了一栏「集成版插件」

打开**外壳设置**（右侧 `⇄` 把手 → 最后一栏「⚙ 外壳设置…」，或托盘右键 →「设置…」），
左侧导航里就在「更新」下面。

每张卡片显示：

| 显示什么 | 说明 |
|---|---|
| 插件名 + 状态标签 | 已装 / 可更新 / 没启用 / **落点丢了** |
| 说明 | 取自插件自己的 `package.json`。**索引里现在是空的**，所以显示「（发布者未填说明）」—— 不编 |
| 线上版本 · 来自哪个仓库 · 大小 · `sha256` 前 12 位 | 装之前就能看清要装的是什么 |
| 按钮 | 没装 →「安装」；本地旧了 →「**更新到 vX.X.X**」；装了 →「卸载」 |

顶上一行给总账：`已装 N / 清单 M`，右边同时报「X 个可更新 · Y 个落点丢了」。

**「检查插件更新」**是真去仓库重拉一次索引 —— 你往 hub 推了新插件或新版本，点它就看到了。
连不上网时**显示上一次缓存并明说是缓存**，不会假装是最新的。

`dsh-plugin-uploader` 这类**开发工具会自动打上「开发者工具」标签**（它不是给终端用户用的）。

## 二、插件从哪来

一个仓库同时提供**索引**与**附件**：

- 索引：`https://raw.githubusercontent.com/18477514055/DSH-Plugin-Hub/main/plugin-index.json`
- 每个版本一个 Release 附件（`<包名>-<版本>.tgz`）

**插件可以住在别的仓库** —— 索引里每条带自己的 `downloadUrl`，界面会显示「来自 owner/repo」。
所以"以后每个插件单独建一个仓库"这条路**不用改外壳**。

## 三、安全边界（说清楚，别以为它比实际更安全）

装插件是这套东西里**最危险**的一件事 —— 装进去的代码会跑在用户的内核里。所以：

- **只有外壳自己的页面能调**。官方 UI 与两个外部站点（`chat` / `platform`）调它一律被拒 ——
  那两个页面里注入着切换把手，谁都能碰到的东西**绝不能有装代码的能力**。
- **页面只能提交"包名"**。下载地址与 `sha256` **传不进主进程** ——
  主进程每次重新拉一次索引、自己挑版本。否则这条通道就成了"从任意 URL 装任意代码"。
- **下载来源是写死的白名单**：只允许 `https` + GitHub 主机。
  10 条负例都验过（含 `github.com.evil.com` 这种**后缀伪装**、`file:`、`javascript:`）。
- **逐个核对 `sha256`**（索引给了就必须对上），**大小对不上就丢弃**（截断是常态）。
- **装之前校验插件本身**：`package.json` 可解析、包名合法、`dsh.bundle.patch` 指向的文件真的在。
  坏插件不是"这个插件没界面"，而是 **`plugin tree failed to load` ⇒ 连累用户所有插件一起起不来**。
- **改 profile 之前必先备份**；备份失败就**拒绝往下写**。
- **写出的 profile 无 BOM**（带 BOM = 整台 DSH 起不来，历史上真发生过）。

**不校验签名** —— 只保证「从我们自己的仓库、经 HTTPS 下载、并且哈希对得上」。

## 四、装完之后要重启一次客户端

插件是内核启动时读 profile 决定的，**装完必须重启一次客户端**才生效。
界面上会明说这一点；本外壳**不会替你重启**（重启会打断你正在生成的回答）。

卸载同理：profile 三处一起撤、落点文件删掉，重启后生效。
**撤回是可逆的** —— 卸载前会备份 profile 到
`<DSH_HOME>\safety\plugin-install-backup\<时间戳>-<动作>-<插件>\`。

## 五、验证方式（真跑，不看自述）

新增 `node scripts/ui-check.js plugins`：起一个**临时环境**（临时 userData + 自己的内核端口），
真开设置页、真拉清单、**真装一个插件**，然后**去磁盘上找证据**：

```
① dependencies 里写了 link:<落点>
② dsh.profile.bundles 里有它
③ node_modules 里有联接，且确实指向那个落点
插件本体落到了 <DSH_HOME>\plugins\<名字>
★ 通过联接真的读得到插件文件（不是「文件在那儿」）
profile package.json 无 BOM
★ 卡片状态跟着变成「已装」
```

连跑 2 次全绿；`ui-check pages` 回归全绿。

另外两份单元验收：

- `node scripts/plugin-catalog-check.js` —— **82 条**（含 10 条下载来源安全负例、容错、版本排序自洽，
  以及**线上真实索引**实测）
- `node scripts/plugin-install-check.js` —— **90 条**（含"与内置插件那条路装出来的 profile
  逐字节相同"的交叉断言）

## 六、这一版**没有**改什么

- **随包内置插件照旧**（`dsh-multi-session` / `dsh-mobile-remote` / `dsh-archive-manager` 仍然随包发）。
  摘掉它们要等首启向导 —— 否则新用户装完是一个空客户端。
- **内核一个字节没动**，外壳仍然零运行时依赖。
- 插件管理器**只列不装**的那部分：没有做"版本历史 / 回滚到旧版本"（那是插件上传器的能力，
  用户侧暂不需要）。
