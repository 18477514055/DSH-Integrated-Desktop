# DSH 集成桌面端 0.2.12

把官方 DeepSeek Harness 内核装进原生 Electron 外壳。**外壳不修改内核的任何文件**；
内核由外部独立安装与升级 —— 升级内核不需要动外壳。

> 这一版就一件事：**集成版插件页多一个「在 npm 上看说明」按钮**。
> 用户原话：「在我们的集成版插件页面那里加一条 npm 官网的地址，如果别人想看说明的话，
> 可以跳转到 npm 那里去查看。」

> ⚠️ **必须重装一次**（不是"重启客户端"）：外壳代码是打进安装目录的，重启不会换代码。

## 一、做了什么

设置页「集成版插件」栏里，每张插件卡片多一个按钮 **「在 npm 上看说明」** ——
点开用系统浏览器跳到 `https://www.npmjs.com/package/<包名>`，看完整说明、版本历史。

## 二、★ 难点不在"加个按钮"，而在"**什么时候不该加**"

如果只是照索引里的名字拼一个 URL，就会出问题。2026-09-24 实测
（`curl registry.npmjs.org/<name>`）：

| 名字 | npm | 出处 |
|---|---|---|
| `dsh-int-plugin-uploader` | **200**（维护者 `zjh18477514055`） | 我们现在的新名 |
| `dsh-int-multi-session` | **200**（同上） | 我们现在的新名 |
| `dsh-plugin-uploader` | **404** | GitHub hub 索引里**当时还挂着**这个旧名 |
| `dsh-multi-session` | **404** | 同上 |

⇒ **照索引名字硬拼，用户点开就是 404 页面，看起来像"我们的包没了"。**

所以 `npmPageOf()` 只在**能证明这个包确实在 npm 上**时才给链接，判据按可靠性排序
（任一条成立即可）：

| # | 判据 | 为什么可靠 |
|---|---|---|
| ① | 索引条目**自己声明** `npmUrl` / `homepage` | 生产端最清楚；★ 但仍**只放行 npm 官网域名**，索引被改坏也带不走用户 |
| ② | 下载地址就是 **`registry.npmjs.org`** 的 tarball | 包名必然存在 |
| ③ | 包名带 **`dsh-int-`** 前缀 | 这是我们自己的命名约定（2026-09-23 第二次改名后的唯一形态），旧名一律不带 ⇒ **天然挡住索引里那些陈旧条目** |

**算不出就返回空串，界面就不画那个按钮** —— 宁可没有链接，也不给一个 404。

## 三、安全边界（与其它插件通道同一条纪律）

**渲染进程只递包名，URL 由主进程重新算。**
新 IPC `dsh:plugins:open-npm` 会：

1. `assertShellSender(e)` —— 只有外壳自有页面能调，官方 UI 与两个外部站点都调不动；
2. 从**主进程自己那份清单**里找这个包名，取它的 `npmUrl`；
3. 找不到 / 算不出 ⇒ 明确拒绝并记日志（`打开 npm 页被拒：… 没有可信的 npm 地址`）。

★ 为什么不收渲染进程递来的 URL：那会把这个通道变成"从设置页打开任意网址"。

## 五、给自己人的两条提醒

1. **这个功能只是第 ③ 件事。** 用户同一天还提了两件，都**没做**，别以为齐了：
   * **① npm 当主渠道**（用户已选定实现方式：**外壳自己从 `registry.npmjs.org` 拉 tarball**，
     **不跑 npm CLI**）—— 详见项目 `AGENTS.md` §2b 的三条理由；
   * **② APK 随插件下发** —— 卡在现在只有 **`app-debug.apk`**（debug 版，不适合发给别人），
     得先出 release 签名版；并且**必须排除 `android/build/` 与 `.gradle`**
     （那里有 232 字符深的路径，超过 Windows 260 上限）。
2. **同版本不算「有更新」** ⇒ 修完/加完功能**必须升版本号**，否则本机那个包永远不会被提示。
   这一版就是因此从 0.2.11 升到 **0.2.12**。
