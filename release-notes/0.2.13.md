# DSH 集成桌面端 0.2.13

**这一版修一条断掉的路：插件清单与插件下载，以前全都走墙掉的主机。**

> 用户原话：「npm 是最官方、最正规的途径，也是**不用梯子也能轻松命令行下载**的途径。」
> —— 这句话点出了一个真实故障，本版就是修它。

---

## 一、问题：没梯子的人，插件页是**整条断的**

2026-09-25 实测（**代理关闭、直连**，已核实注册表 `ProxyEnable=0`、7897 无监听）：

| 主机 | 没梯子时 | 它是干什么用的 |
|---|---|---|
| `registry.npmjs.org` | ✅ **200** | npm 通道 |
| `api.github.com` | ✅ 200 | 外壳「检查更新」 |
| **`raw.githubusercontent.com`** | ❌ **000** | **插件清单** ← 断在这儿 |
| **`github.com`** | ❌ **000** | **插件下载** ← 和这儿 |

⇒ 一个没有梯子的人打开「集成版插件」页：**清单读不到、插件也下不来**。
而他明明能连上 npm —— 我们的插件包**早就发在 npm 上了**（5 个包，20–120 KB）。

**这一版就是把那根管子接上。**

## 二、做了什么

### 1. npm 成为**并列来源**（三层兜底，从强到弱）

| 层 | 来源 | 什么时候用 | 哈希 |
|---|---|---|---|
| ① | **GitHub 索引** | 能连上时 | 我们自己的 **sha256** |
| ② | **npm registry** | GitHub 挂了（**没梯子时的正常路径**） | npm 的 **sha512 integrity** |
| ③ | **本地缓存** | 两条路都挂时，显示上一份并**如实标「这是缓存」** | — |

只有**三层全空**才真的算失败。

### 2. ★ 两种哈希**并存**（它们不能互相转换）

* GitHub 索引给的是 **sha256**（我们生产端算的）
* npm 官方给的是 `dist.integrity` = **sha512-&lt;base64&gt;**

⇒ `installFromArchive` 现在**两条都认**，两个都给就**两个都验**；
一个都不给仍然能装，但**必须**留下"未校验"警告（降级可以走，**不许静默**）。

### 3. 「来源」在界面上是看得见的

卡片上会写 `来自 npm` 或 `来自 18477514055/DSH-Plugin-Hub`，
清单状态行也会说清这次走的是哪条路（`清单更新于…` / `显示的是缓存…`）。

### 4. 顺手治了一个老毛病：**「检查更新」扫过哪里**

设置页「更新」栏会列出**扫过的本机目录**（每条带 `[有]/[无]`）。
这个改动是 0.2.11 那条教训的延续 —— **"搜了一圈没找到"必须能解释**。

## 三、★ 我在这一版里踩的坑（都写进注释了，别重犯）

### 坑 1：第一版设计"永远两边都查再合并" —— **真跑验收当场抓到回归**

npm 上是**新包名**（`dsh-int-multi-session`），而 GitHub 索引里**还挂着旧包名**
（`dsh-multi-session`）⇒ 合并后**同一个插件出现两张卡**。
而"已装"标签是 `mergeInstalled` 按**组名**匹配的 ⇒ 装完刷新时标签落到另一张卡上，
界面表现成 **"装完了还是没装"**。

（`ui-check plugins` 的「★ 卡片状态跟着变成「已装」」实测从 PASS 变 FAIL。
用 `git stash` 回改动前跑同一条，**证明是我引入的**，不是我"以为"的。）

**定稿**：GitHub 能取到时**以它为准**（行为与加 npm 之前一字不差），
npm 只补"hub 里没有的种子包"。取舍写清楚了：**hub 索引里某包版本偏旧时不会自动用 npm 覆盖** ——
版本权威归生产端，npm 只解决"够不够得着"。

### 坑 2：★ 我加的字段被**自己**的归一化悄悄丢掉

我给 npm 源写了 `normalizeNpmLatest`，它正确放上了 `integrity` / `source` / `repo`；
但 `fetchIndex` 最后**又调了一次 `normalizeIndex`** 做合并后的归一化 ——
而它走的是 `normalizeEntry`，那个函数当时**不认这三个字段** ⇒ **静默丢失**。
后果：npm 装插件会退化成"没有哈希可校验"。

⇒ 教训：**加字段时要把"所有会经过的归一化点"都数一遍。**

### 坑 3：我的验收脚本第一版用网络招数制造失败 —— **失败了**

我用 `--host-resolver-rules=MAP raw.githubusercontent.com 127.0.0.1:1` 想掐掉 GitHub，
结果它**照样返回 200** —— 因为本机 Clash 是 **TUN + fake-ip**，域名在代理那边解析，
Chromium 的解析规则根本轮不到。（AGENTS.md §8 早就记过这条，我又栽了一次。）

⇒ 改成用 `fetchIndex` **本来就有的**两个参数（`repo` 指向死仓库、`npm:false`）
确定性地摆出四种场景。**不依赖网络怎么变，结论才硬。**

### 坑 4：一条断言是**竞态**，不是功能坏

`settings.js` 里 `plProg("已装 …")` **写在 `await loadPlugins(false)` 之前** ⇒
"结果文案出现" ≠ "清单刷新完了"。原来刷新快，探针碰巧总赢；
加了 npm 源之后刷新路径变长，**探针就输了**。
⇒ 断言改成**轮询到目标状态**（而不是读一次），并在失败时能看到它停在哪。

### 坑 5：清掉 4 条**长期 FAIL** 的过期断言

它们全都源于同一件事：**2026-09-23 起上传器不再是"开发者工具"**
（用户原话：「我认为它应该是一个普通插件」）—— 代码改了，**断言没跟着改**。

| 位置 | 原断言（过期） | 现在 |
|---|---|---|
| `plugin-catalog-check` ×2 | 上传器应被判 devOnly | 应**不**是 devOnly |
| `plugin-catalog-check` ×1 | 落名单里的名字 ⇒ 开发工具 | 名单已空，锁"机制仍在" |
| `ui-check firstrun` ×1 | 开发者工具默认不勾 | 上传器应**默认勾上**；另立一条用真 dev 条目验规则 |

★ **"长期 FAIL"最坏的地方不是它自己错，而是让真 FAIL 混在噪音里没人看。**
这一版把它们清了，并且**每条都留了一条只依赖本次改动的硬判据**。

**`npm-source-check`（新增）验的四种场景**：

| 场景 | 断言 |
|---|---|
| ① 前置条件 | 死仓库**真的**取不到索引（否则后面结论无意义） |
| ② GitHub 挂 + npm 通 | `ok=true`、`source=npm`、`stale=false`、**失败原因没吞**、≥3 条 |
| ③ 每条都能用 | 下载地址过白名单、带 sha512、sha256 留空、有 npm 说明页 |
| ④ 两条路都通 | hub 说了算、npm 贡献 0 条、**分组名无重复**（锁住坑 1） |
| ⑤ 三层全空 | **如实 `ok=false`**（不假装成功） |
| ⑥ 有缓存 | 退回缓存、`source=cache`、`stale=true` |
| ⑦ 端到端 | **真下载 + 真按 sha512 校验通过**；且**先证明"改一个字符会被拒"** |

★ ⑦ 里那条"先证明尺子对"是刻意的：**只报"校验通过"说明不了校验器在工作** ——
得先让它拒绝一个坏哈希。

## 五、边界（说清楚，别以为它比实际更强）

* **只认 `registry.npmjs.org` 这一个官方主机。**
  `registry.npmmirror.com`（淘宝镜像）实测**更快**（0.2 秒），但那是**第三方镜像** ——
  加进来等于把"装什么代码进用户的家"交给第三方。
  要加应当是一次**显式的信任决定**，不是顺手写进白名单。
* **npm 不给 sha256** ⇒ npm 源的条目 `sha256` 一律留空，**不许瞎填**；
  校验走 sha512 integrity。
* **外壳本身仍然不在 npm 上**（它是 88 MB 的 exe）。
  实测 npm 上真实存在的大包上限约 **108 MB**（`onnxruntime-node`），
  React Native 官方 RFC 记录 **~250 MB 会 E413** —— 88 MB 能发但贴天花板，
  且 npm 版本不可覆盖、不可删，每版永久压 88 MB。
  **所以 exe 仍然走 GitHub Releases + 网盘**，npm 只管插件（20–120 KB）。

## 六、这一版**没做**的（别以为齐了）

* **② APK 随插件下发** —— 仍卡在只有 `app-debug.apk`（debug 版），
  得先出 release 签名版（`android\app\build.gradle` 里连 `signingConfig` 都没有）。
* **手机端扫码器真机验证** —— 插件侧自认的"当前最大的一块空白"。
* **外壳更新也走 npm** —— 见 §五：88 MB 的取舍还没定。
