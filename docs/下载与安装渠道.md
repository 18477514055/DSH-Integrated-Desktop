## 二、外壳（本体客户端）怎么装

### ★ 装之前：内核**不用你装**了（0.2.14 起）

**这一条 2026-09-25 变了 —— 以前是最容易卡住人的地方，现在不用管了。**

这个客户端**只装外壳、不带内核**（刻意如此，这样内核能独立升级）。
但**内核本身也不用你操心**：0.2.14 起，外壳会**替你装**。

* 第一次打开时如果这台电脑上**没有**内核，它会自己从**官方渠道**
  （`registry.npmjs.org`）装一份到**用户数据目录**（`<userData>\kernel\<版本>\`）；
* **不需要你装 Node.js** —— 外壳用 **Electron 自带的 Node** 跑**随包的 npm**
  （npm 本体是纯 JS，11.7 MB，随安装包一起发）；
* **已经有内核就一个字节都不下**，也不会动你已有的任何东西；
* 落点在用户数据目录，**不碰安装目录、不碰全局 npm** ——
  所以 2026-09-19 那次"升级内核把客户端弄坏"的事故面**不在这里**。

三个入口，随便哪个：

| 情况 | 走哪条 |
|---|---|
| 全新机器，客户端起不来 | 加载页会**自动拉开**「诊断与修复」抽屉 → 点「**下载并安装内核**」 |
| 已经进了界面 | **外壳设置 → 更新 → 运行环境** → 勾选后点「开始安装」 |
| 想自己来（老办法，仍然可用） | `npm i -g @deepseek-ai/dsh`（要本机有 Node.js） |

> ⚠️ **别把"装内核"和"升内核"搞混**：
> · **装**（本机一个都没有）⇒ 外壳代劳，装到**独立目录**，失败了最坏是那个目录多个半成品，删掉即可；
> · **升**（换掉全局 npm 里那份）⇒ 仍然**只给命令、由你自己执行**。
>   因为那是往外壳**此刻正在运行的目录**里换代码，2026-09-19 出过
>   "无人值守升级内核导致客户端完全起不来、连逃生通道都失效"的事故，
>   所以这条路刻意留给用户自己走（见 `release-notes/0.2.9.md`）。

⇒ **5 OK / 0 FAIL**）：

> 这个夸克 CLI 的下载通道有**服务端 50 MB 上限**，实测报
> `{"code":23018,"msg":"download file size limit[52428800]"}`（`download` 也没有分段/range 选项），
> 而这一包 109.5 MB ⇒ **没能把文件下载回来重算 sha256**。「哈希一致」这一条**没验到**。
> 想自己核的话，本地这一包的 sha256 是：
> ```
> 5121d69fcd7c515a222daab81ece3712035fef9bd95476565e9fbd52c21945e4
> ```
> 从夸克 App / 网页下载下来后 `Get-FileHash <文件> -Algorithm SHA256` 比一下即可。
> （**别把上面那三条当成"哈希也验过了"** —— 它们能抓的是改名与截断，不是内容被换。）

★ **顺带一条对照**：GitHub Releases 那边（渠道 ①）**是同一天把 4 个附件全下载回来重算过 sha256 的**
（16 OK / 0 FAIL，逐个与 `SHA256SUMS.txt` 和本地文件对上）。所以两个渠道里，
**GitHub 那一条的验收强度更高** ——网盘只做到"名字与大小一致"。

```powershell

npm run pack:netdisk:full     # 再加便携版（约 200 MB）
```

**上传到夸克**（本机装了夸克 CLI 时。**AI 可以代做**，不用你自己点）：

```powershell
$cli = "$env:LOCALAPPDATA\Programs\quarkclouddrive\scripts\quark-drive.cjs"
$fid = "~1Srg8USsDFHUM0KZBbOLhZerDjsTugUPhALxt6uLhPXJ_nUL-u-QCDWeFL9jr5_BDwVwEthz-KHVL3tVxpf4VFs|qzGo_tIoVEw"  # 夸克网盘/DSH-集成桌面端
node $cli upload "release\DSH-集成桌面端-<版本>-网盘包.zip" --parent-fid $fid `
     --session-input "<用户那句话>" --session-id "<本次会话 id>"
```

> ★ `--parent-fid` **必须给** —— 省掉它会报 `upload dir blank`（实测踩过）。
> ★ 上传完**一定要回读核对**：先 `browse --parent-fid $fid --verbose` 把原始输出存成文件，
>   再 `node scripts/verify-quark-upload.cjs <那份原始输出> release\DSH-集成桌面端-<版本>-网盘包.zip`。

>   附件名里的中文被**静默剥掉**、接口照样返回 201。
> ★ **落盘那一步不能用 PowerShell 的 `>`**（默认写 UTF-16，会把 CLI 输出里的中文毁掉）——
>   用 Node 的 `spawnSync` + `fs.writeFileSync(…, 'utf8')` 接（`browse` 现在两种输出形状脚本都吃得下）。
> ★ **一条做不到的**：那个 CLI 的 `download` 有服务端 50 MB 上限（`code 23018`，
>   0.2.15 这天又实测了一次），所以**没法把包下载回来重算 sha256** ——
>   只能验到"文件名逐字符 + 字节数完全一致"。见下面「网盘上怎么找」那一节的缺口说明。

## 三、插件怎么装

现有 **8 个**插件（`dsh-int-*` 命名）。**两个渠道给的东西不一样**，见下表。

### ★ 先说一件容易困惑的事：npm 与网盘包的版本会不一样

| 包名 | npm 上 | 网盘包里（0.2.15） | 说明 |
|---|---|---|---|
| `dsh-int-plugin-uploader` | 0.1.6 | **（没有）** | 网盘包只打 `plugin/` 目录里的插件；上传器本体在第三工作区，没进 `plugin/` |
| `dsh-int-archive-manager` | 0.2.0 | 0.2.0 | 一致 |
| `dsh-int-multi-session` | 0.1.1 | 0.1.1 | 一致 |
| `dsh-int-mobile-remote` | **0.8.0** | **0.11.0** | ⚠️ npm 落后（新版本还没发上去） |
| `dsh-int-session-workspaces` | 0.2.0 | **（没有）** | 同上：本体不在 `plugin/` 里 |
| `dsh-int-context-cap` | **（没有）** | **0.2.0** | ⚠️ 只在网盘包里，npm 上还没发 |
| `dsh-int-im-file-inbox` | **（没有）** | **0.1.0** | ⚠️ 只在网盘包里，npm 上还没发 |
| `dsh-int-wallpaper` | **（没有）** | **0.1.0** | ⚠️ 只在网盘包里，npm 上还没发（**0.2.15 这一包才刚进去**） |

**为什么**：网盘包是照**开发机上 `plugin/` 目录的当前内容**打的
（`make-netdisk-pack.js` 走 `listBundledPlugins`，所以总是最新、且只含**在 `plugin/` 里**的那些），
而 npm 上的是**发过一次就定住**的。两者由不同动作更新，所以天然会错开。

⇒ **要"最新版"就走网盘包；要"省事、稳定、能单独挑"就走客户端里的插件页（走 npm）。**
（这张表 **2026-09-25 随 0.2.15 那包重新逐条实测核对过** ——
npm 侧查 `registry.npmjs.org/<包名>/latest`，网盘侧**解开 zip 读 `插件包/plugin-index.json`**，
不是抄脚本的自述。上一版表里 `dsh-int-wallpaper` 写的还是「还没发到任何渠道」，已订正。）

### 每个插件是干什么的

| 包名 | 干什么 |
|---|---|
| `dsh-int-plugin-uploader` | 插件上传器：把自己写的插件发布出去 |
| `dsh-int-archive-manager` | 归档管理器：侧栏「已归档」分组，可搜索/筛选/永久删除 |
| `dsh-int-mobile-remote` | 手机遥控：扫码用手机看/发消息（**含手机端**） |
| `dsh-int-session-workspaces` | 会话工作区用途 |
| `dsh-int-multi-session` | 多会话：一个弹窗里 N 个输入框，一键发进 N 个新会话 |
| `dsh-int-context-cap` | 上下文上限：模型选择器里加一格，按当前模型给上下文窗口设上限 |
| `dsh-int-im-file-inbox` | IM 文件收件箱：被动扫描 QQ/微信落盘目录，把新文件收进落地区（原件不动） |
| `dsh-int-wallpaper` | 壁纸：上传本机图片当客户端背景，可调亮度与模糊（图片只存本机） |

### 方式 A：在客户端里点着装（**推荐，最省事**）

打开客户端 → **外壳设置 → 集成版插件** → 找到插件 → 点「安装」。

- 卡片上有 **「在 npm 上看说明」** 按钮，想看详细说明就点它（跳到 npm 官网页面）。
- 装完**要重启一次客户端**才生效（宿主在启动时会快照客户端 bundle）。
- 插件**不随包下载** —— 安装包是纯净的，插件按需装。

> 新版客户端里还有**首次安装向导**：第一次启动时会列一屏插件让你勾选，勾完一次装好。

### 方式 B：npm / dsh 命令（会用命令行的人）

```powershell
# ★ 语法以 dsh 自己的 help 为准：dsh plugin --profile <档案> add <包名>
dsh plugin --profile web add dsh-int-mobile-remote
```

> `dsh plugin` 其实是**转发给 pnpm**，在档案目录里执行（默认档案是 `web`）。
> 所以它要求本机有 Node.js，而且**必须带 `--profile`**（不带会报
> `required option '--profile <name>' not specified`）。
> 还想看单个包的信息可以用 `npm view dsh-int-mobile-remote`。

⚠️ **这条路会真的往你的档案里写**（`%APPDATA%\DSH Integrated\dsh-home\profiles\web`）。
想省事又不想碰档案的话，用**方式 A（在客户端里点着装）** —— 客户端装完会提示重启，
而且三处契约（依赖行 / `dsh.profile.bundles` / `node_modules` 联接）由它一次写全。

### 方式 C：离线装（网盘包/别人拷给你）

网盘包里带了插件包目录（`DSH-集成桌面端-插件包\`）。客户端里有 **「本地插件包」** 那条路：
**扫描本机插件包** → 选一个 → 安装。**断网也能用。**

### ⚠️ 关于手机遥控那个插件

`dsh-int-mobile-remote` 是**电脑端 + 手机端**两半：

- **电脑端**：插件装好后在电脑上显示二维码；
- **手机端**：手机扫码打开网页版即可用（`phone/` 目录，扫码就访问得到）。

> **APK 目前还没有随插件下发**（手机端走的是扫码开网页，不需要装 APK）。
> 仓库里那个 `app-debug.apk` 是 **debug 版**，不适合发给别人，所以**没有**放进 npm 包。
> 实测已发布的包里 **11 个文件、0 个 APK**。

## 四、已经装了旧版的人：怎么升级

### 方式 A：客户端里「检查更新」（推荐）

**外壳设置 → 更新 → 检查更新** → 点「下载并安装」。

它会**同时看两个地方**：
- **线上**（GitHub Releases）—— 有没有比你新的版本；
- **本机**（你自己打好的安装包）—— 开发机上 `npm run dist` 的产物也算。

查到新版就下载、启动安装器，**外壳会自己退出**让安装器替换文件（装完安装器会把新版拉起来）。

> ★ 界面上会列出**扫过的本机目录**（带 `[有]/[无]` 标记）。
> 这是 2026-09-24 特意加的：以前"没找到"只报一句「已是最新」，
> 没人知道它到底扫过哪里（那次就是因为没扫到 `release\` 而漏掉了本地新包）。

### 「检查更新」和「检查内核更新」是**两件事**

| 按钮 | 升什么 | 从哪来 |
|---|---|---|
| **检查更新** | **外壳**（我们自己的 exe） | GitHub Releases |
| **检查内核更新** | **内核** `@deepseek-ai/dsh` | **npm 官方源** |

内核升级**故意没有"一键安装"** —— 它只会**下载 + 按官方 sha512 校验 + 给你一条命令**，
那条命令由你自己在终端里敲。理由同上（2026-09-19 的事故）。

### ★★ 内核有**多个发行渠道**：`latest` 不是"最新"

> 用户 2026-09-25 问：「你这个检查内核更新的功能可靠吗？我现在只检测到了一个 0.1.5 的
> 一个小版本，但是现在不是已经跑到 0.1.7 了吗？」

**功能的尺子没错，是信息来源选窄了。** 直连 `registry.npmjs.org` 实测：

```
dist-tags = { latest: "0.1.5-rc.3", next: "0.1.7-rc.2", alpha: "0.1.7-alpha.2" }
0.1.7-rc.2 发布时间  2026-09-24T14:18Z     ← 更新
0.1.5-rc.3 发布时间  2026-09-22T05:55Z
```

⇒ 官方把 `latest` 标签**停在 0.1.5**，把 0.1.7 系列发在 `next` / `alpha` 上。
旧代码查的是 `…/@deepseek-ai/dsh/latest`，所以只能看见一个标签，
还把"正式渠道推荐的那版"说成了"官方最新"。

**现在的做法（0.2.15 起）**：读**整份元数据**，把**全部 dist-tags 都列出来**，
每个渠道各自标「比本机新／旧／同版本」，并特别点出**比正式渠道还新的那些**。

三条口径写死在界面上，避免又被误解：

| | 说明 |
|---|---|
| **默认渠道是 `latest`** | 不替用户把预览渠道当默认。要看别的版本，自己在清单里点 |
| **`npm i -g @deepseek-ai/dsh` 只装 `latest`** | 所以命令行**装不到** 0.1.7。要装别的渠道，只能用**下载下来的那个 `.tgz`**（版本钉在文件名上） |
| **全部渠道里最高的那一版，官方没提升它** | 界面会写明「它不在正式渠道上」—— 这是事实，不是我们的判断 |

### ★★ 但"更新"不等于"能跑"：0.1.7 曾经在外壳上起不来（0.2.15 已修）

渠道清单做出来之后立刻浮出更要紧的一问：这些版本**真的能跑吗**？
真跑过（每条都是一次真启动，见下面的复现命令）—— **两轮**：

**第一轮**：外壳当时带 Electron **37.10.3**

| 内核版本 | 渠道 | 结果 |
|---|---|---|
| `0.1.5-rc.2` | （在用） | ✅ 就绪 |
| `0.1.5-rc.3` | `latest`（正式） | ✅ 就绪 |
| `0.1.7-rc.2` | `next`（预览） | ❌ `Unsupported/no-context` |
| `0.1.7-alpha.2` | `alpha`（实验） | ❌ 同上 |
| `0.1.7-rc.2` | 系统 node 24（对照） | ✅ 就绪 ⇒ **卡的是 Electron，不是内核本身** |

内核自己打的原文：

```
dsh: fatal uncaught exception: Error: dsh: host preparation failed:
node-addon-require-builtin unsupported: Unsupported/no-context
(unsupported Electron runtime fingerprint: Node 22.21.1,
 V8 13.8.258.32-electron.0 (supported Electron versions: 43.0.0, 44.0.0, 45.0.0-alpha.6))
```

表现是加载页**永远停在「正在等待内核就绪…」**。机制（逐文件数出来的）：
`0.1.6` 起 `dsh-app-boot` 新增了 `installRuntimeInterception`
（`0.1.5-rc.3` 里 **0 处**、`0.1.7-rc.2` 里 **3 处**），要 hook V8 内部去 `require` 内置模块，
而它依赖的 `node-addon-native-custom-loader@0.1.6` 只认
`43.0.0 / 44.0.0 / 45.0.0-alpha.6` 的**精确**运行时指纹
（两个内核带的是**同一个**加载器 ⇒ 差别在调用方）。

**第二轮**：把外壳升到 Electron **44.0.0** ⇒ **四个版本全部 ✅ 就绪**，
0.1.6+ 内核因此可用。

> ⚠️ **`electron` 在 `package.json` 里是精确钉死的（`44.0.0`，不带 `^`）**。
> 那个校验比的是 **V8 的精确指纹**，不是版本区间 ——
> 实测 **Electron 44.4.5（当时的最新）同样起不来**。**「顺手升到最新」在这里是错的。**
> 换 Electron 之前先真跑一次：
> `node scripts/kernel-compat-check.js --version=<内核版本> --electron=<装着新 Electron 的目录>`

界面上「能不能跑」这一栏会如实显示四档：**实测能跑 / 实测起不来 / 这个 Electron 上起不来 /
未验** —— 后两档和"实测"分得清清楚楚，不拿推断当证据。

### 想验"某一版内核能不能跟外壳一起用"：两条命令

```powershell
# ① 专门验兼容性：真装 + 真启动，判据是"拿到本机地址"
node scripts/kernel-compat-check.js --version=0.1.7-rc.2
node scripts/kernel-compat-check.js --version=0.1.5-rc.3 --version=0.1.7-rc.2
node scripts/kernel-compat-check.js --version=0.1.7-rc.2 --runtime=node   # 对照组：换成系统 node
node scripts/kernel-compat-check.js --version=0.1.7-rc.2 --electron="C:\path\to\electron44"  # 换一版 Electron 试
#   退出码 0=能跑 2=起不来 3=装不上 4=用法错

# ② 让**既有**的界面验收在指定版本内核上原地跑一遍
node scripts/ui-check.js loading --kernel=0.1.5-rc.3
node scripts/ui-check.js pages   --kernel=0.1.7-rc.2
node scripts/ui-check.js pages   --electron="C:\path\to\electron44"   # 换一版 Electron 跑整套界面验收
```

两者用的都是**外壳自己那条装内核的路**（`src/kernel-provision.js`，随包 npm + Electron 自带的 Node），
装进 `<临时 userData>\kernel\<版本>\` ⇒ 外壳发现链的 **②.5 级「外壳安装」**
（排在**全局 npm 之前**）会优先选中它。判据落在 `shell.log` 里的
`使用内核: <版本>` 与 `内核就绪:` 两行 —— **不是"我们把它装上了"**。

★ 两者全程只写 `%TEMP%`：不碰你正在用的内核、不碰全局 npm、不碰 B / A 两个 DSH 家。

## 五、给自己人：发一个新版要做什么

```powershell
# 1) 升版本号 + 写这一版的说明（缺 release-notes/<版本>.md 会被直接拒绝）
#    改 package.json 的 version；写 release-notes\<新版本>.md

# 2) 打包
npm run dist

# 3) 出发布包（生成 + 审计 github\）
npm run release:bundle

# 4) ★ 必须先 push —— Release 的 tag 打在**远端 HEAD** 上
git push origin main

# 5) 建 Release + 传附件
$env:GITHUB_TOKEN = (gh auth token).Trim()
npm run release:publish

# 6) 回验：把附件**下载回来重算 sha256**，不看脚本自述
```

**三条硬前置**（都不是脚本会替你检查的）：

1. **`release-notes/<版本>.md` 必须先存在** —— 缺它 `release:bundle` 直接拒绝生成。
2. **必须先 `git push` 再建 Release** —— 顺序错了 tag 会指到上一个提交，得删 tag 重来。
3. **工作区里"会进这个包"的文件必须是干净的** —— `package.json` / `src/` / `assets/` /
   `release-notes/` 有未提交改动就会被拦（`docs/` 之类不进包的改动不影响，脚本会说明并放行）。

**发完顺手做**：`npm run pack:netdisk`（给上不了 GitHub 的人）。

## 六、常见问题

**Q：装完打开什么都没有，界面空白？**
A：多半是**没装内核**。0.2.14 起不用你自己装 —— 加载页会**自动拉开**
「诊断与修复」抽屉，点里面的「**下载并安装内核**」即可（约 214 MB，只下一次）。
也可以走「外壳设置 → 更新 → 运行环境」。详见第一节。

**Q：插件装完没反应？**
A：**重启一次客户端**。宿主在启动时会快照客户端 bundle，刷新页面不够。

**Q：为什么安装包里没有插件？**
A：刻意的。包是纯净的（2026-09-22 定的），插件一律按需装 ——
这样你想用哪个装哪个，别人不用的不会占地方，插件也能独立更新。

**Q：我点「检查更新」说已是最新，但我明明有更新？**
A：先看你装的是哪一版。**同版本不算"有更新"**（这是故意的，否则会一直催你升到同一个版本）。
另外「检查更新」看的是**已发布**的版本；如果你手里有个还没发布的本地包，
它会出现在「本机已有新包」那一栏（会显示扫过哪些目录）。

**Q：手机遥控要装 APK 吗？**
A：不用。手机端是**网页版**，扫电脑上的二维码直接用。
