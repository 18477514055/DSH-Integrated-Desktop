# 在官方桌面端复刻集成版（2026-09-29）

> **一句话**：**能复刻的是插件（12 个），不能复刻的是外壳**（三页切换、托盘、加载页、自更新……）。
> 一条命令装一个插件；装完重启官方端即可。

---

## 1. 那边现在是什么（实测，不是推断）

| 项 | 事实 |
|---|---|
| 官方桌面端 | `DeepSeek Harness` **0.2.0-rc.2**，装在 `%LOCALAPPDATA%\Programs\DeepSeek Harness`（2026-09-29 22:07） |
| 它的**家** | `%USERPROFILE%\.dsh` —— **写死的**：它的 `app.asar` 里 `DSH_HOME` 命中 **0** 次、`dshHome` 配置字段 **0** 次；实测把它删掉后一启动就**从零重建**（22:07:31 建了 `profiles\desktop` + `sessions` + `storages`） |
| 它的**档案** | `profiles\desktop`（不是我们这边的 `web`） |
| 它档案里现有 | `dependencies` **空**、`dsh.profile.bundles` = `[dsh-base, dsh-web-app]`、`cordis.yml`（空入口表）、**`cordis.patch.yml`（836 B，有真实内容）** |
| ★ 关键线索 | 它那份 `cordis.patch.yml` 里写着 `agent-default-model` / `ui-settings-account` / `ui-chat` / `ui-settings` 的配置覆盖 ⇒ **那个用户补丁层是被读取的**。而我们每个插件带的 `dsh.bundle.patch`（`cordis.patch.yml`）走的是**同一条链**（每个 bundle 一层补丁） |
| `profiles\desktop\node_modules` | **不存在**（全新档案就是这样；`install-plugin.js` 会自己建空目录 —— 见该脚本 `:189-195`） |

## 2. 能复刻什么 —— **12 个插件**（这才是集成版的价值）

| 包名 | 作用 |
|---|---|
| `dsh-int-multi-session` | 多会话同时开工：一个大弹窗里 N 条提示词分别发进 N 个新会话 |
| `dsh-int-mobile-remote` | 手机遥控：电脑端二维码 + 手机端网页/App |
| `dsh-int-archive-manager` | 侧边栏「已归档」分组 |
| `dsh-plugin-uploader` | 插件校验→打包→装 profile→发布远端 |
| `dsh-int-im-file-inbox` | IM / 微信 / QQ 收件箱 |
| `dsh-int-context-cap` | 模型菜单里的「上下文上限」第三格 |
| `dsh-int-context-viewer` | 上下文查看器 |
| `dsh-int-model-router` | 模型路由 |
| `dsh-int-wallpaper` | 壁纸 |
| `dsh-int-cache-keepalive` | 缓存保持 |
| **`dsh-int-model-search`** ★ 新（0.2.19） | 官方「选择模型」下拉的**搜索框 + 提供方筛选胶囊**（原为外壳注入） |
| **`dsh-int-sidebar-open`** ★ 新（0.2.19） | 侧栏文件树的**用默认应用打开 / 在资源管理器中显示**（原为外壳注入 + IPC） |

## 3. 不能复刻什么 —— 外壳的活（**能力边界，不是懒**）

| 复刻不了 | 为什么 |
|---|---|
| **三页切换**（本机 DSH / DeepSeek 网页版 / 开放平台） | 要 Electron 的 `WebContentsView` + `contentView.addChildView`；插件跑在**网页**里，拿不到视图层。而且那两个站点带 `X-Frame-Options`，iframe 也走不通 |
| 托盘 / 单实例 / 窗口状态记忆 | 原生外壳能力 |
| 加载页 / 首启勾选向导 | 外壳自有页面 |
| 外壳自更新 / **内核**下载与安装 | `src/update.js` / `src/kernel-update.js`，走的是我们自己的 Release 与 npm |
| 设置页「集成版插件」栏 | 外壳自有页面 |
| 两条注入的**兜底** | 官方端没有我们的外壳 ⇒ 那两条功能在那边**只能靠插件**（这正是 0.2.19 把它们插件化的原因） |

⇒ 在官方端上，你得到的是「**内核能力全都在**（12 个插件）」，但**原生外壳体验是他们家的**。

## 4. 怎么装（逐步）

> ⚠️ **这一步会写官方端的家**（`%USERPROFILE%\.dsh`）。按全局规矩**AI 不替你写它** ——
> 命令由**你自己**在终端里跑。脚本每次都会先把 profile 的 `package.json` 备份到
> `<家>\safety\plugin-install-backup\<时间戳>\`，`--revert` 可回退。

```powershell
# 0) 先看一眼现状（只读，什么都不写）
cd "D:\Deepseek工作区\30-DSH客户端\01-集成桌面端"
node scripts/install-plugin.js --plugin dsh-int-model-search --status --home "$env:USERPROFILE\.dsh" --profile desktop

# 1) 逐个装（把 <名字> 换成 §2 表里的包名；两个新插件先装这两个就够试水）
node scripts/install-plugin.js --plugin dsh-int-model-search --apply --home "$env:USERPROFILE\.dsh" --profile desktop
node scripts/install-plugin.js --plugin dsh-int-sidebar-open --apply --home "$env:USERPROFILE\.dsh" --profile desktop

# 2) 全部 12 个一起装（一条循环；装完再重启）
$all = @(
  "dsh-int-multi-session","dsh-int-mobile-remote","dsh-int-archive-manager","dsh-plugin-uploader",
  "dsh-int-im-file-inbox","dsh-int-context-cap","dsh-int-context-viewer","dsh-int-model-router",
  "dsh-int-wallpaper","dsh-int-cache-keepalive","dsh-int-model-search","dsh-int-sidebar-open"
)
foreach ($p in $all) { node scripts/install-plugin.js --plugin $p --apply --home "$env:USERPROFILE\.dsh" --profile desktop }

# 3) 重启官方端（★ 必须重启：宿主在启动时**快照**客户端 bundle，刷新页面不够）

# 4) 想撤掉某一个
node scripts/install-plugin.js --plugin dsh-int-model-search --revert --home "$env:USERPROFILE\.dsh" --profile desktop
```

脚本会改**三处**（缺一处插件就不生效，这也是"装插件不许手敲"的原因）：
profile 的 `dependencies`（`link:` 规格）· `dsh.profile.bundles` · `node_modules\<包名>` 目录联接。

## 5. 装完怎么确认（**别只看脚本说"成功"**）

按硬到软三层看：

1. **界面**：右侧栏文件树有一行，鼠标移上去 → 行尾浮出两个小图标（📂 / ↗）；
   官方「选择模型」下拉里有搜索框 + 提供方胶囊。
2. **页面里的钩子**（DevTools 控制台，官方端 `Ctrl+Shift+I`）：
   ```js
   window.__dshModelSearchStats   // { sweeps, applies, pillBuilds, src: "plugin" }
   window.__dshSidebarOpen.src    // "plugin"
   ```
   `src === "plugin"` ⇒ **是插件在跑**（不是外壳注入，官方端本来也没有外壳注入）。
   `sweeps` 不涨 = 观察器没跑；`hasBar` 类问题看 `applies` / `pillBuilds`。
3. **官方端的日志**：若界面上什么都没有，去找它自己写的内核日志里有没有
   `skipping profile bundle "<包名>"` —— 那一行 = 内核**根本没组合**这个 bundle
   （路径/契约问题），不是我们插件内部的 bug。

## 6. 风险与边界（诚实写清楚）

| # | 风险 / 边界 | 说明 |
|---|---|---|
| 1 | ★ **"官方端是否允许第三方 bundle"没有在真机上确认过** | 我们在 0.1.7 的内核里读到过 `loadProfileDirectory(…, { userLayer?: boolean })` 可跳过用户补丁层 —— 那是"他们**有能力**关掉第三方扩展"的证据，不等于**关掉了**。**第一条实测证据是它自己的 `cordis.patch.yml` 有真实内容 ⇒ 那一层在读。** 但"第三方 bundle 能不能进"必须装完重启看 §5。 |
| 2 | 官方端**会自己重建它的家** | 实测：删掉 `~/.dsh` 后一启动就重建。⇒ 我们的安装落在**它的数据目录**里；将来它若"重置档案 / 换结构"，插件可能被清掉 —— **重跑 §4 那一条循环即可**（这就是脚本存在的意义）。 |
| 3 | `--home` 写的是**绝对路径**，不是 `$DSH_HOME` | 官方端不读 `DSH_HOME`（实测 0 次命中）⇒ 只能显式给 `--home`。 |
| 4 | 我们**不预先校验**官方端的档案名 | 现在写的是 `desktop`（实测存在）。若那边换成别的名字，`--profile` 跟着改即可（脚本会在 profile 目录不存在时明确报错）。 |
| 5 | 两个新插件的**兜底**在官方端没有 | 官方端没有我们的外壳 ⇒ 若插件没生效，那两条功能就是**没有**（不像集成版还有注入兜底）。 |
| 6 | `sidebar-open` 插件的一个已知差异 | 宿主**不校验路径是否存在**（实测：不存在的路径也回 `ok:true`）⇒ 插件版收不到"文件不存在"这类失败提示（注入版当年能报）。详见该插件 README 的「已知边界」。 |

## 7. 复核命令（一条）

```powershell
node scripts/install-plugin.js --plugin dsh-int-model-search --status --home "$env:USERPROFILE\.dsh" --profile desktop
```
（只读：打印这个 profile 里 feed 依赖 / bundles / 联接三处的实际状态。）
