## 二、外壳（本体客户端）怎么装

### ★ 装之前：先确认你有内核

**这是最重要的一条，很多人会卡在这里。**

这个客户端**只装外壳、不带内核**（刻意如此，这样内核能独立升级）。所以第一次用需要先有官方内核：

```powershell
npm i -g @deepseek-ai/dsh
```

前提是本机有 **Node.js**（带 npm）。装完可以用 `dsh --version` 确认。

> 客户端找不到内核时，界面上会直接提示这句 `npm i -g @deepseek-ai/dsh`（`src/main.js:923`）。
> **它不会替你装** —— 内核装在全局 npm 目录里，那是升级内核的地盘，
> 2026-09-19 出过"无人值守升级内核导致客户端完全起不来"的事故，所以这条路刻意留给用户自己走。

## 三、插件怎么装

现有 **6 个**插件（两个渠道的版本**不完全一致**，见下面的表）。

### ★ 先说一件容易困惑的事：npm 与网盘包的版本会不一样

| 包名 | npm 上 | 网盘包里 | 说明 |
|---|---|---|---|
| `dsh-int-plugin-uploader` | 0.1.6 | 0.1.6 | 一致 |
| `dsh-int-archive-manager` | 0.2.0 | 0.2.0 | 一致 |
| `dsh-int-multi-session` | 0.1.1 | 0.1.1 | 一致 |
| `dsh-int-mobile-remote` | **0.8.0** | **0.11.0** | ⚠️ npm 落后（新版本还没发上去） |
| `dsh-int-session-workspaces` | **0.2.0** | **0.2.1** | ⚠️ npm 落后 |
| `dsh-int-im-file-inbox` | **（没有）** | **0.1.0** | ⚠️ 只在网盘包里，npm 上还没发 |

**为什么**：网盘包是照**开发机上插件目录的当前版本**打的（所以总是最新），
而 npm 上的是**发过一次就定住**的。两者由不同动作更新，所以天然会错开。

⇒ **想要最新的用网盘包那条路；想省事、想要稳定版就用客户端里的插件页（走 npm）。**
（这张表 2026-09-24 核对；两边都是"真能装到的版本"。）

### 五个/六个插件各是干什么的

| 包名 | 干什么 |
|---|---|
| `dsh-int-plugin-uploader` | 插件上传器：把自己写的插件发布出去 |
| `dsh-int-archive-manager` | 归档管理器 |
| `dsh-int-mobile-remote` | 手机遥控：扫码用手机看/发消息（**含手机端**） |
| `dsh-int-session-workspaces` | 会话工作区用途 |
| `dsh-int-multi-session` | 多会话 |
| `dsh-int-im-file-inbox` | IM 文件收件箱 |

### 方式 A：在客户端里点着装（**推荐，最省事**）

打开客户端 → **外壳设置 → 集成版插件** → 找到插件 → 点「安装」。

- 卡片上有 **「在 npm 上看说明」** 按钮，想看详细说明就点它（跳到 npm 官网页面）。
- 装完**要重启一次客户端**才生效（宿主在启动时会快照客户端 bundle）。
- 插件**不随包下载** —— 安装包是纯净的，插件按需装。

> 新版客户端里还有**首次安装向导**：第一次启动时会列一屏插件让你勾选，勾完一次装好。

### 方式 B：npm / dsh 命令（会用命令行的人）

```powershell
# ★ 语法以 dsh 自己的 help 为准：dsh plugin --profile <档案> add <包名>
dsh plugin --profile web add dsh-int-mobile-remote
```

> `dsh plugin` 其实是**转发给 pnpm**，在档案目录里执行（默认档案是 `web`）。
> 所以它要求本机有 Node.js，而且**必须带 `--profile`**（不带会报
> `required option '--profile <name>' not specified`）。
> 还想看单个包的信息可以用 `npm view dsh-int-mobile-remote`。

⚠️ **这条路会真的往你的档案里写**（`%APPDATA%\DSH Integrated\dsh-home\profiles\web`）。
想省事又不想碰档案的话，用**方式 A（在客户端里点着装）** —— 客户端装完会提示重启，
而且三处契约（依赖行 / `dsh.profile.bundles` / `node_modules` 联接）由它一次写全。

### 方式 C：离线装（网盘包/别人拷给你）

网盘包里带了插件包目录（`DSH-集成桌面端-插件包\`）。客户端里有 **「本地插件包」** 那条路：
**扫描本机插件包** → 选一个 → 安装。**断网也能用。**

### ⚠️ 关于手机遥控那个插件

`dsh-int-mobile-remote` 是**电脑端 + 手机端**两半：

- **电脑端**：插件装好后在电脑上显示二维码；
- **手机端**：手机扫码打开网页版即可用（`phone/` 目录，扫码就访问得到）。

> **APK 目前还没有随插件下发**（手机端走的是扫码开网页，不需要装 APK）。
> 仓库里那个 `app-debug.apk` 是 **debug 版**，不适合发给别人，所以**没有**放进 npm 包。
> 实测已发布的包里 **11 个文件、0 个 APK**。

## 四、已经装了旧版的人：怎么升级

### 方式 A：客户端里「检查更新」（推荐）

**外壳设置 → 更新 → 检查更新** → 点「下载并安装」。

它会**同时看两个地方**：
- **线上**（GitHub Releases）—— 有没有比你新的版本；
- **本机**（你自己打好的安装包）—— 开发机上 `npm run dist` 的产物也算。

查到新版就下载、启动安装器，**外壳会自己退出**让安装器替换文件（装完安装器会把新版拉起来）。

> ★ 界面上会列出**扫过的本机目录**（带 `[有]/[无]` 标记）。
> 这是 2026-09-24 特意加的：以前"没找到"只报一句「已是最新」，
> 没人知道它到底扫过哪里（那次就是因为没扫到 `release\` 而漏掉了本地新包）。

### 「检查更新」和「检查内核更新」是**两件事**

| 按钮 | 升什么 | 从哪来 |
|---|---|---|
| **检查更新** | **外壳**（我们自己的 exe） | GitHub Releases |
| **检查内核更新** | **内核** `@deepseek-ai/dsh` | **npm 官方源** |

内核升级**故意没有"一键安装"** —— 它只会**下载 + 按官方 sha512 校验 + 给你一条命令**，
那条命令由你自己在终端里敲。理由同上（2026-09-19 的事故）。

## 五、给自己人：发一个新版要做什么

```powershell
# 1) 升版本号 + 写这一版的说明（缺 release-notes/<版本>.md 会被直接拒绝）
#    改 package.json 的 version；写 release-notes\<新版本>.md

# 2) 打包
npm run dist

# 3) 出发布包（生成 + 审计 github\）
npm run release:bundle

# 4) ★ 必须先 push —— Release 的 tag 打在**远端 HEAD** 上
git push origin main

# 5) 建 Release + 传附件
$env:GITHUB_TOKEN = (gh auth token).Trim()
npm run release:publish

# 6) 回验：把附件**下载回来重算 sha256**，不看脚本自述
```

**三条硬前置**（都不是脚本会替你检查的）：

1. **`release-notes/<版本>.md` 必须先存在** —— 缺它 `release:bundle` 直接拒绝生成。
2. **必须先 `git push` 再建 Release** —— 顺序错了 tag 会指到上一个提交，得删 tag 重来。
3. **工作区里"会进这个包"的文件必须是干净的** —— `package.json` / `src/` / `assets/` /
   `release-notes/` 有未提交改动就会被拦（`docs/` 之类不进包的改动不影响，脚本会说明并放行）。

**发完顺手做**：`npm run pack:netdisk`（给上不了 GitHub 的人）。

## 六、常见问题

**Q：装完打开什么都没有，界面空白？**
A：多半是**没装内核**。看第一节，先 `npm i -g @deepseek-ai/dsh`。

**Q：插件装完没反应？**
A：**重启一次客户端**。宿主在启动时会快照客户端 bundle，刷新页面不够。

**Q：为什么安装包里没有插件？**
A：刻意的。包是纯净的（2026-09-22 定的），插件一律按需装 ——
这样你想用哪个装哪个，别人不用的不会占地方，插件也能独立更新。

**Q：我点「检查更新」说已是最新，但我明明有更新？**
A：先看你装的是哪一版。**同版本不算"有更新"**（这是故意的，否则会一直催你升到同一个版本）。
另外「检查更新」看的是**已发布**的版本；如果你手里有个还没发布的本地包，
它会出现在「本机已有新包」那一栏（会显示扫过哪些目录）。

**Q：手机遥控要装 APK 吗？**
A：不用。手机端是**网页版**，扫电脑上的二维码直接用。
