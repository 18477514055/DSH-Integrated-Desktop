## 三、第 1 条：白底黑鲸鱼图标

### 3.1 形状从哪来（不是自己画的）

`src/whale-path.json` —— 官方 `dsh-web-frontend/dist/favicon.svg` 里那条 `<path d="…">`
按 `M` 拆成的 4 段：`body`(1743) / `belly`(673) / `eye`(301) / `spout`(677)。
2026-09-20 从社区工程 `4.DSH桌面版定制\src\whale-path.json` 原样搬入
（`sha256 FE1700A15B639E5E836E97D00BD398F571B9ED3C1EFA83FF72753D9087711B0F`，3460 字节）。

★ 顺带纠正一个认知：**官方 favicon 在浅色模式下是不可见的** ——
它的 `<svg>` 带 `fill="none"`，只有 `@media (prefers-color-scheme: dark)` 才把 path 填白。
所以这里不复用官方 svg，而是自己画布明确指定两色。

### 3.2 填充方式

不依赖 nonzero 环绕数（body 逆时针 + 三个顺时针镂空），而是
**先画黑色身体、再用白色把 belly/eye/spout 三个孔盖回去** —— 换渲染器也不会画错。

### 3.3 产物

| 文件 | 尺寸 | 用在哪 |
|---|---|---|
| `assets/icon.png` | 512 | 窗口图标（`main.js` 的 `iconPath()`） |
| `assets/icon-256.png` | 256 | 备用 |
| `assets/icon.ico` | **16/24/32/48/64/128/256 多尺寸，内嵌 PNG** | **exe 的文件图标 + 桌面/开始菜单快捷方式图标 + 安装器图标** |
| `assets/tray.png` | 32（缩放 0.94） | 托盘 |
| `assets/tray@2x.png` | 64 | 高分屏托盘（Electron 按 `@2x` 自动选用） |

- 快捷方式指向 exe，图标即 exe 内嵌图标 ⇒ 桌面图标、文件图标都由 `icon.ico` 决定；
  已在 `package.json` 里把 `build.win.icon` / `nsis.installerIcon` / `nsis.uninstallerIcon`
  三处都指向它。
- 生成：`npm run icon`（= `electron scripts/make-icon.js`）
- 逐像素验证：`npm run verify:icon`（= `node scripts/verify-icon.js`）
- 打包前自动补齐并验证：`npm run dist` 的前置 `node scripts/ensure-icon.js`

### 3.4 三个踩过的坑（脚本里都写了注释）

1. **`ELECTRON_RUN_AS_NODE=1` 会让脚本必崩**：Electron 退化成纯 Node，
   `require("electron")` 返回的是 npm 包里的**指路字符串**，解构出的 `app` 是 undefined。
   本机 DSH 给工具子进程就设了这个变量（实测 `=1`）。
   ⇒ `make-icon.js` 开头有显式检查并提示 `Remove-Item Env:\ELECTRON_RUN_AS_NODE`。
2. **别"每个尺寸开一个离屏窗口"**：实测连续开关时 16×16 能成、24×24 直接
   `ERR_FAILED (-2) loading 'data:text/html…'`（窗口创建/销毁竞态）。
   ⇒ 改成**一张页面两个格子、只加载一次**（左=应用母图、右=托盘母图），
   再用 `capturePage(rect)` 各取一半，最后降采样出全部尺寸。
3. **守卫条件写错过一次**：`whenReady` 在 **`app`** 上，不在 electron 模块上。
   写成 `typeof probe.whenReady` 会让守卫永远为真，把一次能跑通的渲染误判成环境问题。

### 3.5 验证器的断言也写错过一次（值得记）

第一版 `verify-icon.js` 断言"黑色外接框宽高都 ≈ scale"，四条全红：

```
FAIL  icon.png 鲸鱼大小接近设定缩放 0.84  — 实测 0.811x0.607
```

**图是对的，尺子是错的** —— 鲸鱼天然横宽（外接框约 1.33:1），不可能同时满足 0.84×0.84。
改成断言"**长边** ≈ scale"+"宽高比落在 1.20~1.50"。
（这正是 `AGENTS.md` 里"先证明尺子对，再报结论"那条。）

### 3.6 真实验证结果

```
[icon.png]      尺寸 512 ✓｜四角+四边中点 8/8 不透明纯白 ✓｜透明像素 0 ✓
                黑 24.5% ✓｜居中 dx=0.29% dy=0.29% ✓｜长边 0.811（设定 0.84）✓
                宽高比 1.334 ✓｜包围盒内白色 48.5%（镂空在）✓
[icon-256.png]  同理全过（黑 24.0%，长边 0.809，比例 1.335）
[tray.png]      同理全过（黑 22.9%，长边 0.875，比例 1.400）
[tray@2x.png]   同理全过（黑 27.0%，长边 0.891，比例 1.357）
[icon.ico]      7 张，**每张内嵌 PNG 的 IHDR 真实尺寸与目录项声明一致**（独立复核，非脚本自报）
```

## 五、第 3 条：模型列表的搜索框 + 提供方筛选（运行时注入）

`src/inject/model-search.js`，由 `main.js` 在官方 UI **每次 `did-finish-load`** 时
用 `webContents.executeJavaScript()` 执行一次（跑在页面主世界，不受页面 CSP 限制）。

### 5.1 锚点只用官方**语义属性**，不用哈希类名

从 `client.js` 读到的真实结构（0.1.5-rc.2）：

```html
<div role="menu" aria-label="…">                  ← createPortal 到 body
  <button role="menuitem">选择模型…</button>
  <button role="menuitem">推理强度…</button>
  <div class="…groups scrollable">
    <section role="group" aria-labelledby="<id>">  ← 一个提供方一组
      <div id="<id>" class="…groupTitle">提供方名</div>
      <button role="menuitemradio" title="模型名" aria-checked="…">…</button>
    </section>
  </div>
</div>
```

⇒ 用 `div[role="menu"]` + `section[role="group"][aria-labelledby]` +
`button[role="menuitemradio"][title]`，**一个 `_7KE1Ra_*` 哈希类名都不碰**；
提供方名字从 `aria-labelledby` 指向的元素取。

`/model` 那个命令弹窗走的是 `commandUi` 的 popupSelect（**没有** `role="group"`），
所以不会被误伤。

### 5.2 一个决定性的细节：搜索框必须插在**菜单内部**

官方根节点上挂着 `onBlur`（`client.js:525-528`）：

```js
const onBlur = (event) => {
  if (event.relatedTarget instanceof Node &&
      (rootRef.current?.contains(event.relatedTarget) === true ||
       menuRef.current?.contains(event.relatedTarget) === true)) return;
  close();
};
```

⇒ 焦点只要落在 `root` **或 `menu`** 内部就不会关菜单。
菜单是 `createPortal(..., document.body)` 出来的，**不在 root 子树里** ——
所以搜索框**必须插进 `menuRef` 那个 `div[role="menu"]`**，否则一点它就关菜单。

本实现插在 `groupsContainer.parentElement` 的 `groupsContainer` 之前；
而分组容器是 Fragment 的直接子节点（**Fragment 不产生 DOM 节点**），
⇒ `groupsContainer.parentElement` **就是菜单本体** ⇒ 满足条件。

### 5.3 过滤用"隐藏行"，不重画列表

只给不匹配的行加 `data-dsh-ms-hide="1"`，用**我们自己的样式表** `display:none`。
React 不管理这个属性、re-render 也不会删它；万一节点被重建，`MutationObserver` 会再补一次。
（自己的改动会触发 observer ⇒ 用 `st.applying` 标志避免自激循环。）

### 5.4 交付的行为

- 搜索框（大小写不敏感、匹配 模型名 `title` + 行内文字 + 提供方名）
- 提供方胶囊：`全部 N` + 每个提供方 `组名 N`，点一下只看该组、再点取消；
  **只在分组数 > 1 时出现**（只有一个分组时白占地方）
- 筛到 0 条时给「没有匹配的模型（共 N 个）」+ 一键复位；**真的没有模型**时用官方原文（不抢）
- 输入框里按 **Esc 先清空搜索/筛选**（再按一次才关菜单）
- 每次开关菜单自动重置（菜单是 React unmount/remount，状态天然是新的）
- `--no-inject` 启动参数可整个关掉注入（不改代码就能先关）

### 5.5 失败方式：安静退出

所有 DOM 查找都在 `try` 里，找不到就什么都不做。
**官方改版 ⇒ 用户看到的就是官方原样，不会把菜单弄坏。** 最坏结果是"没有搜索框"。

### 5.6 有意没做的：不自动聚焦搜索框

当年那版会"切到模型列表时焦点自动落到搜索框"。这次**没做**：
按 `ArrowDown` 在 `role="menu"` 上做 roving focus，抢焦点会破坏键盘导航。
⇒ 需要点一下搜索框才能输入。**如果用户希望自动聚焦，说一声就加。**

## 七点五、验证过程中抓出来的三个真 bug（都不是需求本身）

这三个都是**"真跑真看"才暴露的**，靠读代码和 `node --check` 一个都发现不了。
它们的共同点是：**平时不发作，一发作就是"界面什么都没有"**。

### bug 1 · 复用已有内核时把 401 地址当成可加载地址（**原有代码就有**）

`ensureServer` 的复用分支原来是：

```js
const probe = await K.probeDsh(primary);          // primary = http://127.0.0.1:PORT（裸 origin）
if (K.isProbeAlive(probe)) { serverUrl = primary; ... }   // ← 把裸 origin 当成了能加载 UI 的地址
```

但 `dsh web` 的带 token 地址**只在启动时打印一次**，裸 origin 一律 401：

```
GET /?token=…   → 303 + Set-Cookie: dsh-auth… (Max-Age=2592000)
GET /           → 401 "dsh web authentication required; reopen the URL printed by dsh web."
```

⇒ 复用成功的那一刻，界面就已经注定打不开了。
**触发条件**：端口上有一个**不是本客户端起的** dsh（例如桌面 `启动DSH.cmd` 起的浏览器模式内核，
或者别的实例留下的），而客户端默认端口也是 3080。

**修法**（双向都做）：
- 自己起内核时把 `{pid, port, url, dshHome, profile}` 记到 `<userData>/kernel.json`；
  复用前先核对（pid 活着 + 端口/家/档案都一致）→ 用记录里的**带 token 地址**。
- 核对不上时退回裸 origin，但打上 `reuseUnverified`，加载后确认一次；
  确认被 401 挡住就**给一页人话**（说清原因 + 三条出路），而不是把那行英文甩给用户。
- 退出时删记录（内核已被杀，留着是垃圾）。

### bug 2 · `showStatus` 在导航成功之前就把状态置成"已在状态页"

`loadFile(status-page.html)` 会以 `ERR_ABORTED (-3)` 失败（当 webContents 正在加载别的页面时）。
一次失败就让外壳**永远认为自己在状态页上**，再也不导航 ⇒ 界面卡在中间态。

**修法**：加载失败重试（最多 5 次），并且**重试前先确认"现在还真的需要状态页"**。

### bug 3 · IPC 来源判据用"意图标志"而不是"事实上屏幕里是什么"

原来用主进程维护的 `shellPageActive` 判断"主窗口现在是不是显示外壳页面"。
但 `loadUi()` 会在**决定**离开状态页的那一刻就把它置 false，而页面此时**还在屏幕上、脚本还在跑**
⇒ 页面一次正常的 `getSnapshot()` 被拒，界面上直接出现：

```
读初始状态失败：Error invoking remote method 'dsh:state':
  Error: 拒绝：主窗口当前显示的不是外壳页面
```

**修法**：改判 `event.senderFrame.url` —— 主进程侧看到的**已提交 URL**，
既伪造不了，也天然等于"屏幕上现在是什么"。

> 顺便记一笔：改这个的时候我把 `let shellPageActive` 的声明删成了注释，
> 但**三处赋值还在**。`node --check` 查不出来（语法合法），
> 而 `"use strict"` 下赋值给未声明变量会在运行期抛 `ReferenceError`。
> 已经用一个"裸标识符赋值 vs 声明表"的小脚本扫过一遍确认清干净了。
> **教训：删声明的时候必须同时扫赋值点。**

## 十、已知限制 / 待办

1. **搜索框不自动聚焦**（理由见 5.6），需要点一下。
2. 注入依赖官方 DOM 的**语义属性**。官方若改掉 `role="menu"` / `role="group"` /
   `role="menuitemradio"`，搜索框会**静默消失**（不会弄坏界面）。
3. `clean` 档案是运行时按需创建的（`<DSH_HOME>/profiles/clean/{package.json,cordis.yml,cordis.patch.yml}`），
   `node_modules` 镜像交给内核的 `healProfilesModuleFallback()` 建。
   **首次纯净启动能否一次成功，需要用户真按一次来确认。**
4. `fallback-client` 用"在安装目录里认主程序"的方式定位 exe，
   认不出时会给出候选列表而不是硬编码路径。
5. 加载页的进度条**不是**真实百分比（内核不汇报启动进度），只在真实里程碑跳。
