# 「点提供方胶囊 ⇒ 整个模型列表消失」——根因与修复（2026-09-26）

> 用户原话：**「我试过了，只有全部和 Deepseek 两个标签能用，其他的一点就列表消失。」**
> 涉及文件：`src/inject/model-search.js`（外壳注入官方「选择模型」菜单的搜索框 + 提供方胶囊）、
> `scripts/ui-check.js`（`inject` 模式，新增永久回归闸门）。

## 一、症状与第一层误判

菜单里那排胶囊是 `全部 N / <提供方> n / …`。点「全部」和**当前提供方**（用户当时是 DeepSeek）
正常筛选；点**任何别的提供方**，整个下拉连同列表一起消失。

第一反应是"筛选算法把行藏多了"。**这个判断是错的**：事件级探针显示，
我们的 `click` 处理器**跑到了、筛选也算对了**（夹具那组 `2/2` 可见、其它组 `0` 行），
真正消失的是**整个菜单**。

## 二、根因（四步链，每一步都有出处）

| # | 事实 | 依据 |
|---|---|---|
| ① | 官方根节点上写着 `onMouseDown: if (target.closest("button")) preventDefault()` | 官方 `dsh-client-ui-model-selection/lib/client.js:709-711` |
| ② | 菜单是 `createPortal(…, document.body)`，我们的搜索条插在 `MenuSurface` 里 | 同上 `:744-749`；注入脚本的 `groupsContainer.parentElement` 就是 `menuRef` |
| ③ | 因此**真鼠标点胶囊时焦点不会落到胶囊上** —— React 的合成事件**沿 React 树冒泡**（portal 也算），这条 `preventDefault()` 对我们的胶囊同样生效 | 探针实测：`click` 事件里 `document.activeElement` 仍是「当前选中那一行」 |
| ④ | 官方开菜单时会把焦点 `focus()` 到**当前选中的那一行**；我们一旦把**那一行所在分组** `display:none`，焦点掉到 `<body>`；官方根节点的 `onBlur` 发现 relatedTarget 既不在 rootRef 也不在 menuRef ⇒ `close()` | 官方 `:547`（聚焦选中行）、`:648-651`（onBlur→close）；探针实测 `focusout relatedTarget=null, active=BODY` |

### 为什么恰好是"只有全部和当前那个提供方能点"

* 点**全部**：不藏任何东西 ⇒ 焦点那一行不动 ⇒ 菜单不关。
* 点**当前提供方**那一颗：被藏的是**别的**分组，焦点那一行还活着 ⇒ 菜单不关。
* 点**任何别的提供方**：藏掉的正是**焦点所在分组** ⇒ 焦点掉到 body ⇒ 菜单关闭。

## 三、为什么从 0.2.0 到 0.2.16 一直没被测出来

1. `ui-check inject` 原先**只数胶囊个数**（`pills.length === groups + 1`），一颗都没点过。
2. 临时家里通常只有 **1 个提供方** ⇒ `names.length > 1` 不成立 ⇒ 胶囊根本不出现。
3. **最关键**：其它地方（`plugin-check` 等）点元素用的是 `el.click()` ——
   它**只派发一个 `click`，不产生 mousedown / focus / focusout**。
   而这个 bug 的破坏力**完全来自焦点那条链**，用 `el.click()` 永远复现不出来。

## 四、修法（`src/inject/model-search.js`）

1. **焦点保护（修复本体）**：`apply()` 改成"**先算、再救焦点、后落属性**"三步。
   落 `display` 之前，如果 `document.activeElement` 正落在**即将被藏起来**的那一行/那一段里，
   先把焦点收进我们的搜索框（仍在 `menuRef` 内 ⇒ 官方 `onBlur` 放过 ⇒ 菜单不关）。
   **顺序绝不能反**：先藏再收，焦点已经掉出去了，收不回来。
2. **按元素身份认领分组**（不再拿分组名字符串当筛选依据）：官方把分组名渲染成
   `group.name`（官方 `:829`；宿主侧 `dsh-api-session-controller/lib/index.js:526`），
   提供方重新注册/名册刷新时 React 只改文本节点 ⇒ 旧实现存下来的字符串会一个分组都匹配不上。
   现在胶囊记住它代表的那一段；元素真被重建了才退回按名字找；**都认不出来就放开筛选**
   （宁可显示全部，绝不把列表藏空）。
3. **观察菜单内部的 `characterData`**（作用域只到菜单，不扫整页，免得正文流式输出狂触发），
   让"分组改名"后胶囊标签跟着更新；同时把空态 DOM 改成**只在内容真变时才重建**，
   消掉一个 60ms 的自我触发循环。
4. **胶囊行样式**：`flex:none` + `max-width:180px`（超长名省略号 + `title` 全名）、
   换行最多两行后内部滚动，避免提供方多时把整个菜单吃掉。

## 五、验收（真跑，不看自述）

`node scripts/ui-check.js inject` 新增 7 条断言（默认夹具补第二个提供方，让胶囊出现）：

* 胶囊数 = 分组数 + 1；
* **逐颗真鼠标点击**：点某颗后**只剩该提供方的行**、且**菜单没关**；
* 点「全部」恢复全量；
* ★ **把分组标题原地改名**（只动文本节点）后，① 标签跟着更新、② **再点同一颗胶囊仍然只剩它的行**
  —— 这一条就是用户报的"一点列表就消失"的永久闸门。

2026-09-26 连跑 4 次全过（`inject` 模式）。自诊断计数挂在 `window.__dshModelSearchStats`
（`sweeps/applies/pillBuilds/watch`）—— 出问题先看它，不用猜。

## 六、顺带核对（同一个 bug 类）

`plugin/dsh-multi-session` 的模型下拉**不受影响**：它的 `onBlur` 是刻意空实现
（`lib/client.js:1027`，注释写明"不用 blur 关"），所以焦点被藏走也不会关面板。
