**"独立复算"的含义**：把 Release 附件**下载回来**，用 PowerShell
`Get-FileHash -Algorithm SHA256` 重算，与索引里那条逐字节比。
**不看上传脚本自己的 ✅**（项目验证纪律：文件存在/接口返回 201 都不构成凭据）。

复核命令（一条看全部）：

```powershell
$idx = Invoke-RestMethod "https://raw.githubusercontent.com/18477514055/DSH-Plugin-Hub/main/plugin-index.json?t=$((Get-Date).Ticks)" -Headers @{'User-Agent'='dsh'}
foreach ($e in $idx.entries) {
  $f = Join-Path $env:TEMP ("v-"+$e.name+"-"+$e.version+".tgz")
  curl.exe -sL -o $f $e.downloadUrl
  "{0,-24} v{1,-8} {2}" -f $e.name,$e.version,((Get-FileHash -Algorithm SHA256 -LiteralPath $f).Hash.ToLower() -eq $e.sha256.ToLower())
}
```

## 三、怎么再发一版（顺序不能换）

```powershell
cd D:\DSH工作区002\1.DSH插件上传器
$env:GITHUB_TOKEN = (gh auth token).Trim()      # token 只进进程，不落盘

# ① 只打包（不装、不联网）—— 想看产物大小与成员就用它
node scripts\uploader-cli.js build "D:\deepseek-workspace\5.DSH集成桌面端\plugin\<名字>"

# ② 体检（只读）
node scripts\uploader-cli.js validate "D:\...\plugin\<名字>"

# ③ 真发：装进一个**临时家** + 归档 + 发布 + 内部回下载核验
$dshTmp = Join-Path $env:TEMP 'dsh-upload-home\DSH Integrated\dsh-home'
node scripts\uploader-cli.js upload "D:\...\plugin\<名字>" --home "$dshTmp" --profile web --publish --note "<说明>"
```

**六个已经踩过的坑**（每一条都真发生过）：

1. **`$home` 是 PowerShell 的只读自动变量**（= `$HOME`）。`$home = ...` 会**赋值失败**，
   于是 `--home` 收到 `C:\Users\<用户名>`，上传器就在**用户目录**下建 `profiles\` 与 `safety\`。
   ⇒ 变量名用 `$dshTmp` 这类。**已发生一次，现场已清理，没有发出任何东西。**
2. **别用 PowerShell 把 JSON 传给 node**：`'{"name":"x"}'` 里的双引号会被剥掉
   （实测落地成 `{name:x}`），于是 `JSON.parse` 报 `Expected property name`。
   ⇒ 让**node 自己构造 JSON**。
3. **`fetch failed` 可能是偶发的**：同一条命令重试一次就过。
   判断依据要独立取：`curl.exe` 与 `node -e "fetch(...)"` 各自打一次
   （实测本机 `node v24.20.0`：直连 200、走 Clash 7897 也 200）。
4. **`publish` 只能发台账里已有的版本** ⇒ 先 `upload` 过一次才有得发；
   但 `upload` 失败在发布那一步时，**归档与台账已经写好了**，直接 `publish <包名>` 重试即可，
   **不必重跑 `upload`**（重跑会再装一次）。
5. **PowerShell 读含中文的台账会报 `ConvertFrom-Json` 转义错误** ——
   那是**控制台按 GBK 解码 UTF-8** 的假象，**文件没坏**。要读就用 node 读。
6. **`--note` 传中文会被 PowerShell 编码搞坏**（台账里会留下乱码），本轮用的是英文。

## 五、两处打包实现不一致（2026-09-21 实测，会咬人）

同一个插件，**外壳的打包**与 **hub 的 `npm pack`** 对"什么该带走"判得不一样：

| 走哪条路 | `dsh-mobile-remote` 打出来 |
|---|---|
| **外壳**（`extraResources` → `<安装目录>\resources\plugins`） | **40 个文件 / 2.09 MB**，零联接 |
| **hub**（`uploader-cli build` → `npm pack`） | **181 个文件 / 6.17 MB** |

根因：外壳的 `src/plugins.js` 有一份 `DEFAULT_EXCLUDES`
（`**/.gradle/**`、`**/android/build/**`、`**/android/app/build/**`），
而 **`npm pack` 不认它** —— 那条规矩只写在插件自己的 `android\.gitignore` 里，
而 npm **只读根目录**的 `.npmignore` / `.gitignore`，子目录里那份它看不见。

⇒ **同一条"不要传给别人"的规矩，两个打包器一个遵守、一个不遵守。**
将来发布 `dsh-mobile-remote` 时**必须先补一个根目录 `.npmignore`**，
否则 hub 上那份会比外壳里那份脏 4 倍，而且带 175 字符深路径（见 §二）。

**教训（可以推广）**：规格写在 A 处、执行在 B 处，就迟早会分叉。
这条规矩真正的家，应该在**两个打包器都读得到的地方**（插件根目录的 `.npmignore`），
而不是只在 `android\` 里、只被 git 读到。

## 七、0.2.6 落地：干净包 + 首启向导（2026-09-22）

§6 那张"到那天要改的就三处"的清单**已全部执行**，一字不差。这一节记的是执行结果、
以及**为什么这么设计**（下次要动它之前先读完）。

### 7.1 摘包：确实只动了 `package.json`

| 改了什么 | 结果 |
|---|---|
| `build.extraResources`（`runtime/materialized-plugins` → `plugins`） | **删掉** |
| `pack` / `dist` / `dist:portable` 里的 `node scripts/materialize-plugins.js &&` | **删掉** |
| `src/plugins.js` 的 `provision()` | **一个字节没动**（§6 第 3 条要求的正是这个） |

`provision()` 在来源目录不存在时 `listBundledPlugins()` 返回空 ⇒ `ok=true` 空转
（`src/plugins.js:289-293` 与 `:370-374`）。**所以老用户不会掉插件**：
它只写"来源目录里有的那些"，从不去删家里已有的东西。

### 7.2 这条承诺现在由机械断言盯着，不再靠人记得

`npm run verify:asar` 原来把「`resources\plugins` 在不在」**打印一句**就完事。
0.2.6 起它是**断言**：

```
asar 内 plugin/ 目录存在: false（必须 false —— 插件不进 asar）
resources/plugins 存在: false（干净包：不带内置插件）
结论：10 个文件、NN 个功能标记全部命中；结构性检查全过（干净包）
```

谁把 `extraResources` 或 `build.files` 里的 plugin 加回来，`verify:asar` 立刻 FAIL
（并把"该改哪两处、别只改 package.json"印在失败信息里）。

### 7.3 首启向导：三条判据同时成立才自动弹

`src/main.js` 的 `firstRunDue()`：

1. `<userData>\first-run.json` 里没有 `done:true`（标记文件的世界只有 `src/first-run.js` 一个文件懂）；
2. `firstRunAutoEnabled()` —— **默认只在 `app.isPackaged` 时自动弹**；
3. **这个家里一个插件都没有**（`PI.listInstalled()` 纯本地扫描，不联网）。

第 3 条是为了**从 0.2.5 升上来的老用户**：他们的插件本来就装好了，不该被问一遍。
第 2 条那条"开发机默认不弹"不是洁癖，是**六个验收脚本全都用全新的临时
`--user-data-dir` 起真客户端** —— 开发模式也弹的话，每个脚本都会多出一个设置窗口、
多一个 CDP page 目标，把它们基于 `waitForPage` 的判据全搅乱。
⇒ 要主动验它用 `DSH_FIRST_RUN=force`（`ui-check firstrun` 就是这么干的），
用户想关掉它用 `DSH_FIRST_RUN=off`。

**时机**：`maybeAutoOpenFirstRun()` 只在 `bootstrap()` 里、`loadURL` 成功之后调一次。
早了不行 —— 装插件要写 profile 三处契约，而**全新机器上 profile 是内核第一次跑起来才建的**。

### 7.4 向导为什么做成"设置页的一个栏"，而不是一个新窗口/新页面

- 装插件的能力（`dsh:plugins:*`）已经在主进程里了，**再开一套窗口就要再写一遍 UI**；
- 「集成版插件」栏与向导读的是**同一份** `pluginState`（主进程算的唯一真相）⇒ 不会互相矛盾；
- 老用户随时能从「集成版插件」栏的「打开首次安装向导」回去 —— 同一个 `switchPane`；
- 代价：窗口标题默认是「设置 · …」，要单独 `setTitle()` 换成「欢迎使用 · …」。
  ⚠️ **只传 `new BrowserWindow({ title })` 没用** —— 页面自带 `<title>` 时选项会被**忽略**
  （Electron 文档明说）。必须在 `did-finish-load` 之后 `setTitle()`。

### 7.5 顺手修掉的真 bug：`dsh:settings:focus-pane` 一直丢

主进程是在设置页 `did-finish-load` 那一刻 `send()` 的，而页面要 `await getEnv()` 之后
才 `ipcRenderer.on` 订阅 —— 两个时刻没有保证。实测**那条消息丢了**：
托盘点「检查更新…」会把窗口打开，但停在「常规」栏、也不会自动查一次。
**首启向导走的是同一条路** ⇒ 不修的话向导会停在「常规」，用户根本看不到勾选清单。

修法：订阅提前到 **settings.js 的同步执行期**，先记下 pane，等 `boot()` 把各栏接好线再补做。

### 7.8 ★ 附带发现：`ui-check loading` 一直在确定性失败（**不是本轮改出来的**）

本轮回归时 `node scripts/ui-check.js loading` 稳定 `11 PASS / 2 FAIL`。**连跑 4 次全一样**，
说明不是抖动。做了 A/B（只把 `src/main.js` 暂存回改前版本，其余文件不影响加载页）：

```
我的改动版 : run1..4 → exit=1  PASS=11 FAIL=2
基线（改前）: run1..2 → exit=1  PASS=11 FAIL=2   ← 同样的两条
```

⇒ **与 0.2.6 的改动无关，是既有问题。** 掉的两条是：

```
FAIL  「环境体检」真跑并返回结果码        （runAction 返回 undefined）
FAIL  体检输出已流回页面（output 面板非空）（收集到 0 字符）
```

**真因（时间戳证据，来自应用 shell.log）**：`health-check` 要跑一个 PowerShell 体检脚本
（本机实测 5~15 秒，看机器忙不忙），而**内核大约 10 秒就绪**，`loadUi()` 一就绪就把主窗口
从加载页切到官方 UI：

```
18:07:08  启动
18:07:11  [shell] 执行动作: health-check
18:07:18  [shell] 内核就绪: http://127.0.0.1:3177/?token=***
```

⇒ 用户（和检查脚本）**眼看着体检输出打到一半，页面被整个切走**，输出全丢 ——
而诊断的全部意义就是看那份输出。后面那条 `dsh:diag:list` 被拒
（`拒绝：当前显示的不是外壳自有页面（http://127.0.0.1:3177/）`）只是同一个原因的下一次发作。

**为什么不在这轮顺手修**：这不是一行能补的。要让检查变绿，必须选一种产品行为 ——
① 诊断动作在跑时**不切页**（但动作跑完仍会立刻切走，检查脚本那条"跑完 1.5 秒后读输出"
   依然会撞上）；② 诊断**跑完后给一段宽限期**再切（一个刻意的魔法秒数）；
