**"独立复算"的含义**：把 Release 附件**下载回来**，用 PowerShell
`Get-FileHash -Algorithm SHA256` 重算，与索引里那条逐字节比。
**不看上传脚本自己的 ✅**（项目验证纪律：文件存在/接口返回 201 都不构成凭据）。

复核命令（一条看全部）：

```powershell
$idx = Invoke-RestMethod "https://raw.githubusercontent.com/18477514055/DSH-Plugin-Hub/main/plugin-index.json?t=$((Get-Date).Ticks)" -Headers @{'User-Agent'='dsh'}
foreach ($e in $idx.entries) {
  $f = Join-Path $env:TEMP ("v-"+$e.name+"-"+$e.version+".tgz")
  curl.exe -sL -o $f $e.downloadUrl
  "{0,-24} v{1,-8} {2}" -f $e.name,$e.version,((Get-FileHash -Algorithm SHA256 -LiteralPath $f).Hash.ToLower() -eq $e.sha256.ToLower())
}
```

|---|---|---|---|

**越过 Windows 260 的经典上限**。排除后是 55+27+65 = 147，安全。

而"排除"这件事**不用我判断该排除什么** —— 插件自己写了答案，

★ **为什么单靠它不生效**：npm 只认**插件根目录**的 `.npmignore` / `.gitignore`，

所以将来要发时，在插件根放一个 `.npmignore` 写上 `.gradle/` 与 `build/` 即可 ——
**加法，不改它任何一行代码**；android 源码与 `app-debug.apk` 全部保留。

## 三、怎么再发一版（顺序不能换）

```powershell
cd D:\DSH工作区002\1.DSH插件上传器
$env:GITHUB_TOKEN = (gh auth token).Trim()      # token 只进进程，不落盘

# ① 只打包（不装、不联网）—— 想看产物大小与成员就用它
node scripts\uploader-cli.js build "D:\deepseek-workspace\5.DSH集成桌面端\plugin\<名字>"

# ② 体检（只读）
node scripts\uploader-cli.js validate "D:\...\plugin\<名字>"

# ③ 真发：装进一个**临时家** + 归档 + 发布 + 内部回下载核验
$dshTmp = Join-Path $env:TEMP 'dsh-upload-home\DSH Integrated\dsh-home'
node scripts\uploader-cli.js upload "D:\...\plugin\<名字>" --home "$dshTmp" --profile web --publish --note "<说明>"
```

**六个已经踩过的坑**（每一条都真发生过）：

1. **`$home` 是 PowerShell 的只读自动变量**（= `$HOME`）。`$home = ...` 会**赋值失败**，
   于是 `--home` 收到 `C:\Users\<用户名>`，上传器就在**用户目录**下建 `profiles\` 与 `safety\`。
   ⇒ 变量名用 `$dshTmp` 这类。**已发生一次，现场已清理，没有发出任何东西。**
2. **别用 PowerShell 把 JSON 传给 node**：`'{"name":"x"}'` 里的双引号会被剥掉
   （实测落地成 `{name:x}`），于是 `JSON.parse` 报 `Expected property name`。
   ⇒ 让**node 自己构造 JSON**。
3. **`fetch failed` 可能是偶发的**：同一条命令重试一次就过。
   判断依据要独立取：`curl.exe` 与 `node -e "fetch(...)"` 各自打一次
   （实测本机 `node v24.20.0`：直连 200、走 Clash 7897 也 200）。
4. **`publish` 只能发台账里已有的版本** ⇒ 先 `upload` 过一次才有得发；
   但 `upload` 失败在发布那一步时，**归档与台账已经写好了**，直接 `publish <包名>` 重试即可，
   **不必重跑 `upload`**（重跑会再装一次）。
5. **PowerShell 读含中文的台账会报 `ConvertFrom-Json` 转义错误** ——
   那是**控制台按 GBK 解码 UTF-8** 的假象，**文件没坏**。要读就用 node 读。
6. **`--note` 传中文会被 PowerShell 编码搞坏**（台账里会留下乱码），本轮用的是英文。

## 五、两处打包实现不一致（2026-09-21 实测，会咬人）

同一个插件，**外壳的打包**与 **hub 的 `npm pack`** 对"什么该带走"判得不一样：

| 走哪条路 | `dsh-mobile-remote` 打出来 |
|---|---|
| **外壳**（`extraResources` → `<安装目录>\resources\plugins`） | **40 个文件 / 2.09 MB**，零联接 |
| **hub**（`uploader-cli build` → `npm pack`） | **181 个文件 / 6.17 MB** |

根因：外壳的 `src/plugins.js` 有一份 `DEFAULT_EXCLUDES`
（`**/.gradle/**`、`**/android/build/**`、`**/android/app/build/**`），
而 **`npm pack` 不认它** —— 那条规矩只写在插件自己的 `android\.gitignore` 里，
而 npm **只读根目录**的 `.npmignore` / `.gitignore`，子目录里那份它看不见。

⇒ **同一条"不要传给别人"的规矩，两个打包器一个遵守、一个不遵守。**
将来发布 `dsh-mobile-remote` 时**必须先补一个根目录 `.npmignore`**，
否则 hub 上那份会比外壳里那份脏 4 倍，而且带 175 字符深路径（见 §二）。

**教训（可以推广）**：规格写在 A 处、执行在 B 处，就迟早会分叉。
这条规矩真正的家，应该在**两个打包器都读得到的地方**（插件根目录的 `.npmignore`），
而不是只在 `android\` 里、只被 git 读到。

**为什么现在不该摘**：摘掉内置插件之后，新用户开箱就是**一个插件都没有 + 没有任何途径装**
—— 因为替代它的插件管理器（`plugin-catalog.js` + 清单界面 + 首启勾选）**还没写**，
目前只完成了安装内核 `src/plugin-install.js`。

⇒ **摘包必须和插件管理器在同一个版本里发**（预定 0.2.5）。
单独先摘包 = 开箱空的。

**到那天要改的就三处**：

1. `package.json` → `build.extraResources` 里那条 `runtime/materialized-plugins` → `plugins`，删掉；
2. `package.json` → `pack` / `dist` / `dist:portable` 三条脚本里的 `node scripts/materialize-plugins.js &&`，删掉；
3. `src/plugins.js` 的 `provision()` **保留不动** —— 来源目录不存在时 `listBundledPlugins` 返回空、
   `provision` 直接 `ok=true` 什么都不做，正好是"干净包"该有的行为；
   开发机要临时塞内置插件时它仍然可用（`DSH_BUNDLED_PLUGINS=auto`）。

⚠️ 用户自己的机器不受影响：B 家那三条 dev link 会被 `provision` 判为"已有的外部 link"而**尊重不接管**，
摘包前后都一样。
