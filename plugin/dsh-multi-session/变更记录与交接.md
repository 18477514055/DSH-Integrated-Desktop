## 契约要点（改任何一处前先读）

它是本仓库里**唯一目录名与包名一致、且本体就在仓库内**的插件，
所以它也是"三处契约"最容易看错的一个：

| # | 位置 | 值 |
|---|---|---|
| ① | `package.json` 的 `name` | `dsh-multi-session` |
| ② | `cordis.patch.yml` 的 `id` 与 `name` | 同上（`name` 是 loader 的**模块标识符**，不是显示名） |
| ③ | `lib/client.js` 的 `__ModuleLoader__.load({ id })` | 同上 |
| ④ | 用户 profile | `dependencies` 键 / `dsh.profile.bundles` 条目 / `node_modules` 联接 |

## 曾踩过的坑

- **`ctx.slots.register` 必须包在 `ctx.slots.inject(槽位名, () => …)` 里，且是方法调用形式** ——
  槽位由父级 entry 声明，声明前 register 会**同步抛错**；摘成局部变量会丢 `this.ctx`。
- **不许用 `conversation.sendSession` 提交带附件的内容** —— 它会 await 乐观回显的"退休"，
  而新建会话没被跟随 ⇒ promise 可能**永不结算**、按钮永久卡在"发送中…"。
  改用 `fileUpload.upload` + `face.prompt()`（完成语义有界）。
- **命令菜单与 `@` 引用菜单的候选源**要判 `unavailable`，不能把"内核没提供"当成"没有候选"。
