## 契约要点（改任何一处前先读）

它是本仓库里**唯一目录名与包名一致、且本体就在仓库内**的插件，
所以它也是"三处契约"最容易看错的一个：

| # | 位置 | 值 |
|---|---|---|
| ① | `package.json` 的 `name` | `dsh-multi-session` |
| ② | `cordis.patch.yml` 的 `id` 与 `name` | 同上（`name` 是 loader 的**模块标识符**，不是显示名） |
| ③ | `lib/client.js` 的 `__ModuleLoader__.load({ id })` | 同上 |
| ④ | 用户 profile | `dependencies` 键 / `dsh.profile.bundles` 条目 / `node_modules` 联接 |

## 2026-09-26 内核 0.1.7 适配：图标跨世代（**这个插件一度整个不见了**）

用户原话：「那个多对话插件，它现在无法呈现出来了，或许不兼容，建议你进行一次优化。」

**根因（实测，不是推断）**：插件用的是 **0.1.5 那代的图标名** ——
`IconQueueOutline14` / `IconCheckOutline16` …（数字后缀 = 默认尺寸）。
内核 0.1.7 的 `dsh-client-ui-primitives` 里**没有这些名字**，只有
`IconXxxRegular` / `IconXxxMedium` / `IconXxxArtwork`（尺寸走 `size` 属性）。
⇒ 12 个图标全是 `undefined` ⇒ `h(undefined, …)` ⇒ **React error #130**
⇒ 官方对**每个槽位条目**有独立错误边界，条目被渲染成空。

**为什么以前查不出来**：现象是「`apply()` 跑了、两个槽位注册都 `ok:true`、界面上什么都没有」，
看起来像"没加载 / 不兼容"；`npm run plugin:check` 当时也只报"等 45 秒也没出现"。
真正的线索在**页面控制台**（那个脚本原来没抓）：

```
slot entry crashed in 'conversation.input.right': Error: Minified React error #130
```

⇒ 记一条定位手段：**槽位条目渲染期崩掉，只会出现在页面 console，不会出现在插件的任何自述里。**

**修法**：加 `iconAcrossGenerations(stem, size)` —— 按 0.1.7 的名字优先
（`Regular` → `Medium` → `Artwork` → 旧名字），**取不到就返回一个渲染 `null` 的组件**
（绝不能返回 `undefined`，那等于把整条条目再炸一次）。12 处调用点全部改走它。
⇒ 同一个包在 **0.1.5 与 0.1.7 上都能用**；将来某个图标再改名，也只是少一个图标，不会整个插件消失。

**复验（`npm run plugin:check`，真跑）**：修前 **8 项 FAIL**（触发按钮等 45 秒不出现、弹窗不渲染、
0 个输入框…）→ 修后 **3 项 FAIL**，界面与交互全过：触发按钮 / 弹窗 / 两行输入 /
模型下拉（搜索 354→16、来源胶囊、分组）/ `/` 命令 / `@` 引用 / 附件 / Esc 三级行为。

### ⚠️ 还剩 3 项 FAIL，**没有修**（写在这里，免得下次又当成"已经好了"）

```
✗ 标记文本 A 出现在磁盘上的持久数据里（提示词真的发出去了）: 全盘没找到
✗ 标记文本 B 也出现在磁盘上（两条都真的发出去了）: 全盘没找到
✗ 附件的字节出现在宿主数据里（附件真的上传了）: 全盘没找到附件内容
```

结果视图自己说的是：`会话已创建，但拿不到它的会话面（binding 为空）`。
⇒ **会话真的建出来了**（临时家 `sessions/` 下出现了三个 `session.v4.jsonl.zstd`），
但**拿不到它的 session binding**，所以提示词根本没发出去。
★ 顺带一个线索：**0.1.7 的会话格式是 v4**（写出的是 `session.v4.jsonl.zstd`），
而本仓库别处还按 v3 造夹具 —— 下一轮修发送路径时要连这个一起核。

## 曾踩过的坑

- **`ctx.slots.register` 必须包在 `ctx.slots.inject(槽位名, () => …)` 里，且是方法调用形式** ——
  槽位由父级 entry 声明，声明前 register 会**同步抛错**；摘成局部变量会丢 `this.ctx`。
- **不许用 `conversation.sendSession` 提交带附件的内容** —— 它会 await 乐观回显的"退休"，
  而新建会话没被跟随 ⇒ promise 可能**永不结算**、按钮永久卡在"发送中…"。
  改用 `fileUpload.upload` + `face.prompt()`（完成语义有界）。
- **命令菜单与 `@` 引用菜单的候选源**要判 `unavailable`，不能把"内核没提供"当成"没有候选"。
