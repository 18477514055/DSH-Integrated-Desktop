# 接手必读：这个插件改过名（2026-09-22）

> **给对话/人的一句话**：`dsh-archive-manager` 已改名为 **`dsh-int-archive-manager`**，
> 版本 `0.1.0 → 0.2.0`。**仓库里的目录名刻意保持旧名没动** —— 别"顺手改回去"，
> 那会当场弄坏已装的插件。下面是为什么、以及改名要同时动哪几处。

---

## 一、为什么改名

查公开生态时发现这个名字**已经被别人占用**：

| 位置 | 占用者 | 时间 |
|---|---|---|
| npm | `dsh-archive-manager` **1.1.1**，maintainer **jasonrale** | 2026-08-15 起 |
| dsh-plugin.org（社区插件市场，非官方） | 同名收录 **48 个**（michengai / z953218350 / chushiz …），**没有一个是我们的** |

后果：我们自己分发没问题（走自己的索引 + sha256 + 本地包），但在公开生态里**等于没有身份** ——
别人搜这个名字，看到的是别人的插件。所以加 `dsh-int-` 前缀拿到一个干净的名字。

（同批改名的还有 `dsh-mobile-remote → dsh-int-mobile-remote`。
`dsh-multi-session` / `dsh-plugin-uploader` 在 npm 与社区站上都干净，**没动**。）

## 二、★ 改名必须同时改这几处，漏一处内核直接起不来

| # | 位置 | 改成什么 | 漏了会怎样 |
|---|---|---|---|
| ① | `package.json` 的 `name` | `dsh-int-archive-manager` | 内核按 profile 里的键解析包名，对不上就找不到包 |
| ② | `cordis.patch.yml` 的 `id` **与** `name` | 同上 | 报 `declares no dsh.bundle`；`name` 是 loader 的**模块标识符**，写成显示名会 `ERR_MODULE_NOT_FOUND` |
| ③ | `lib/index.js` 的 `const name` | 同上 | bundle 公告的名字与实际不符 |
| ④ | `lib/client.js` 的 `__ModuleLoader__.load({ id })`、`PLUGIN_ID`、`PANEL_ID` | 同上 | 浏览器半边注册不上 / 面板 id 与侧边栏条目的配对断掉 |
| ⑤ | **用户的 profile 三处契约** | 键名 / bundles 条目 / `node_modules` 联接 | 装了也加载不了（见下） |

第 ⑤ 处不在本目录里，在用户的 DSH 家里：

```
<DSH_HOME>\profiles\web\package.json   → dependencies 的键、dsh.profile.bundles 的条目
<DSH_HOME>\profiles\web\node_modules\dsh-int-archive-manager   → 目录联接（指向本目录）
```

**换包名不能热更**（要重新解析 `node_modules`）⇒ 用户必须**重启一次客户端**。

## 三、★ 目录名为什么没跟着改（别改）

仓库里的 `plugin\dsh-archive-manager` 是一个**目录联接**，指向本体
`D:\DSH工作区002\2.归档管理器`。而：

- 已装插件在 profile 里的 `link:` 是**写死的绝对路径**；
- `node_modules` 里那个联接也指过来。

两边都是绝对路径 ⇒ **改目录名 = 当场弄坏这个插件**（全局规矩：联接两头都不能改名/搬家）。
所以：**包名是新名，目录名与路径一律保持旧名。**
外壳的验收脚本因此把两者拆成两个常量：`PLUGIN_NAME` / `PLUGIN_DIR_NAME`。

## 四、名字的映射表（照着改，别猜）

| 旧 | 新 |
|---|---|
| `dsh-archive-manager`（包名） | `dsh-int-archive-manager` |
| `dsh-archive-manager`（目录名，**不动**） | `2.归档管理器`（本体，**不动**） |
| 版本 `0.1.0` | `0.2.0` |

HTTP 路由前缀没有包名（本插件走 `/dsh-archive/*`），**不受改名影响**。
