> ★ **接手前先读 [`改名与交接-20260922.md`](./改名与交接-20260922.md)**：
> 这个插件 2026-09-22 由 `dsh-mobile-remote` 改名为 `dsh-int-mobile-remote`（0.3.0 → 0.4.0，

> 📁 **本目录是插件的"本体"**。2026-09-21 起它住在**第三工作区**
> （`D:\DSH工作区002\3.dsh-int-mobile-remote\`），而集成板仓库里的
> `5.DSH集成桌面端\plugin\dsh-int-mobile-remote` 是一个**指向这里的 Junction（目录联接）** ——
> 已装插件的 `link:` 与 `node_modules` junction 因此**一字未改**就照样能用。

## 两条路，选一个

| | ① 浏览器（零安装） | ② Android App（WebView 壳） |
|---|---|---|
| 怎么开始 | 用**系统相机**扫电脑上的**第一个**二维码 | 先装 `android/` 编出的 APK，再扫**第二个**二维码 |
| 手机要装东西吗 | **不用** | 要装 APK |
| 体验 | 有图标（可"添加到主屏幕"），但地址栏在、非独立窗口 | 无地址栏、独立任务、桌面图标 |
| 功能 | **完全一样**（App 就是个全屏 WebView，加载的是同一个页面） | 同左 |

> 装了 App 就扫**第二个**码（`dshmr://` 深链，扫到直接进 App）；
> 没装 App 就扫**第一个**（普通 http，任何相机都能扫、开浏览器）。
> 两个码内容不同但功能一致 —— 电脑端弹窗里都给了。

| 指标 | 改前 | 改后 |
|---|---|---|
| 一屏可见会话行 | **8 行**（行高 78px） | **11 行**（行高 61px） |
| 列表总高 | 12319px | **9573px**（−22%） |
| 一屏可见消息数 | **6 条** | **8 条** |

1. **列表行变紧**：padding 12→9、行距 8→6、标题 15→14.5px、元信息 12→11.5px、

3. **发送键改成 44px 圆形图标**（纸飞机）：原来是 64px 的文字键「发送」，

4. **图标按钮 38→44px**：原尺寸低于 Android 建议的 48dp，也低于手指好点的经验下限 40px。

### ① 键盘挡住输入框（"整个页面也会被挡住一半"）

**真因不是 CSS 写错，是 Android 平台的强制行为**：本 App `targetSdk = 37`，
而 **Android 15（API 35）起强制 edge-to-edge** ⇒
`windowSoftInputMode="adjustResize"`（Manifest 里写了）**被系统忽略**，
键盘是**盖**上来的而不是把窗口顶上去 ⇒ 网页里 `100dvh` 量到的仍是"没键盘"的高度。

**三层一起修，缺一层都治不住**：

| 层 | 做法 | 位置 |
|---|---|---|
| 网页 | 跟 `visualViewport` 把**真实可视高度**写进 CSS 变量 `--app-h`，`body` 用它当高度（键盘一弹 body 立刻变矮，flex 把输入框顶到键盘之上） | `web/app.js` 的 `syncViewport()`、`web/styles.css` 的 `body{height:var(--app-h,100dvh)}` |
| 原生 | `OnApplyWindowInsetsListener` 把键盘让出的高度做成 root 的**底部 padding**（零第三方依赖，没用 androidx） | `android/.../MainActivity.java` 的 `installKeyboardInsetHandler()` |
| 主题 | 再显式写一遍 `windowSoftInputMode` + `windowLightNavigationBar` | `android/app/src/main/res/values/themes.xml` |

**为什么三层都要**：网页侧依赖 WebView 正确实现 `visualViewport`（多数 ROM 上没问题，
但不是全部）；原生侧拿到的是系统给的真 inset，更硬。`--app-h` 用 CSS 变量而不是直接改
`body.style.height`，是为了**没有 JS / JS 报错时能自然回退到 `100dvh`**（不会变成高度 0）。

### ② 右下角两个图标"不知道是干什么用的"

**真因**：原来是 emoji（`🖼` / `🕘`），而 emoji 由**系统字体**渲染 ——
颜色、粗细、字形在不同手机上都不一样，有的还变成黑白方框。

**已全部换成单色线性 SVG**：跟着 `currentColor` 走（浅色主题下自动是深色）、
粗细统一、任何设备长得一模一样，不受字体影响。
换掉的不只那两个：顶栏的新建 / 刷新 / 更多 / 返回 / 模型 / 中断，以及配屏页的品牌图标也都是 SVG。
（按钮另有 `aria-label` 完整说明，无障碍与自动化验证都读它。）

### ③ 电脑连手机热点反而扫不上（同一个 Wi-Fi 反而能连）

**真因不是"热点不通"，是二维码里编了错的地址。** 两个独立原因，都实测复现过：

1. **同属私网段的地址是平局，谁先枚举到就选谁。**
   旧判据只有"是不是私网"，可热点一开，Windows 的 **Wi-Fi Direct 虚拟网卡**
   （`本地连接* 1`）就会拿到 `192.168.137.1` —— 它**也是私网**，于是和 WLAN 的真实地址打成平局，
   `sort` 对 0 不保序 ⇒ 结果取决于 `networkInterfaces()` 的枚举顺序。实测复现（只换枚举顺序）：
   ```
   WLAN 在前        → 选中 192.168.43.5   ✅
   本地连接* 1 在前 → 选中 192.168.137.1  ❌ 那是电脑自己的热点网关，手机连不上
   ```
   表现就是"有时能用有时不能"，而且**跟手机怎么连没关系**。
2. **Clash / Meta 之类的 TUN 虚拟网卡**会带一个非私网地址（本机是 `198.18.0.1`），
   并且**抢默认路由**（本机 `0.0.0.0/0` metric=0 指向 Meta 隧道）⇒ 流量被接管，局域网也不通。

**现在的判据**（`desktop/index.js` 的 `lanAddresses()`，按分数排序）：
排除虚拟网卡（接口名匹配 Wi-Fi Direct / TUN / WireGuard / AnyConnect / Hyper-V / VMware…）、
排除 `192.168.137.*`（Windows 热点固定网关）、排除 RFC 2544 基准网段 `198.18.0.0/15`
（Clash TUN 实测就用它），真网卡名加分，**平局时按接口名再比一次**（不让枚举顺序决定结果）。
另外电脑端弹窗里**列出备选地址** —— 首选连不上时能直接换一个。

> ★ 两个判据互为补充，缺一不可：本机那个 TUN 适配器的**接口名就叫 `Meta`**，
> 不含 tun/vpn 任何关键词 ⇒ 只靠名字会漏；所以又按**地址段**兜了一层。
> （这是探针抓出来的：只写名字判据时，"只有 TUN"那一条断言 FAIL。）

### ④ 工具调用 / 思考过程要像电脑那样折叠

> **这一条是本插件最值得读的一处 bug**：症状（白屏）离真因（一个字符串比较写错）极远，

**真因：看门狗的判据恒为假。** 三处代码凑成的：

| 位置 | 写的什么 |
|---|---|
| `remember()` | 存的是 `u.getScheme()+"://"+u.getHost()+":"+u.getPort()` ⇒ **无尾斜杠** |
| WebView | `getUrl()` 返回**规范化后**的地址 ⇒ **带**尾斜杠 |
| 看门狗 | `cur.equals(watchdogUrl)` ⇒ **恒为假** ⇒ 超时永不触发 ⇒ **白屏无出口** |

**实测复现（真 Chromium，不是推断）**：
```
传入 "http://127.0.0.1:3110"   → location.href = "http://127.0.0.1:3110/"   equals? false
传入 "http://127.0.0.1:3110/"  → location.href = "http://127.0.0.1:3110/"   equals? true
```

**★ 为什么"扫码那条路没事、只有冷启动白屏"**（这条正好对上用户的原话）：
扫码回来拼的是 `"http://" + host + ":" + port + "/"` —— **带**尾斜杠，恰好与规范化结果相等
⇒ 看门狗只在扫码后有效。**"必须扫码才能进"就是这个形状。**

**第二处漏判**：死地址 TCP 挂起时连接还没提交，`getUrl()` 返回 **null**，
旧判据（`cur.equals(...)`）同样为假 ⇒ 最常见的失败反而漏得最干净。

**修法（三层，缺一层都还有白屏）**：

1. **URL 规范化比较**：`sameUrl()` 忽略尾斜杠差异（不放松成前缀匹配 —— 那会误判重定向）；
2. **补 `cur == null` 分支**：未提交也算超时；
3. **局域网自动找电脑**（`autoDiscover`）：连不上就**自动**扫一遍 /24 网段 ——
   零权限（`NetworkInterface`）、32 并发、**真网实测 254 个地址 5.7 秒**；
   判据是**页面里有 `dsh手机遥控` / `pairView`**，不是"端口开着"
   （否则同网段任何一个 3110 服务都会被误认成电脑）；
4. **token 跨 origin 交接**（`saveToken`/`getToken`/`clearToken`）：找到新 IP 也没用 ——
   token 存在 localStorage，而 **localStorage 按 origin 隔离**，换了 IP 就换了 origin。
   现在由壳（App 私有 SharedPreferences）代管一份。

**验收**：`plugin-check-mobile-remote` 里新增 6 条**静态断言**盯着这处修复
（旧判据已清除 / null 分支在 / `sameUrl` 在 / `autoDiscover` 在 / 判据是页面标记 / token 三桥）。
★ 诚实标注：**这不是真机验证**（本机没有 Android 设备），
它保证的是"改对了、没改回去"；行为证据是上面那次真 Chromium 复现 + 真网扫描实测。

**⑥ 文件互传（2026-09-22）** —— 用户原话：「允许连接之后的手机和电脑DSH互传文件。
这方便了一些跨端项目中，我可以随时下载电脑那边的文件。」
**⑦ 跨工作区（2026-09-22）** —— 用户原话：「我们的整个工作其实已经迁移到第2个工作区了，
有没有办法让手机可以下载三个工作区的文件？以及向三个工作区发送文件。」

> ★ 两个方向**刻意走了两条完全不同的通路**，因为 RPC 是 JSON 进 JSON 出：
> 正文进内存、还要 base64（体积 ×4/3）、两端都得整个装下、且没有任何进度。

| 方向 | 怎么走 | 为什么这么走 |
|---|---|---|
| **电脑 → 手机** | RPC `file.download` 只**签一张一次性票据** → 字节走 `GET /api/file/dl?t=…`，交给**系统下载管理器**（App 内走 JS 桥 `dshNative.download`） | 那是一个**普通 URL** ⇒ 原生进度、通知栏、断点续传，**字节全程不经过 JS**，WebView 不会被大文件撑爆 |
| **手机 → 电脑** | `POST /api/file/ul?…`，请求体就是**裸字节**，宿主 `pipeline()` 边收边落盘；进度用 XHR 的 `upload.onprogress` | 不在内存里堆积；串行上传（并行会让"总进度"变成糊涂账，且热点带宽本来就窄） |

**下载**（在「选电脑文件」里点到任意文件 → 「下载到手机」）：
- 票据**一次性**（用过即焚）、**2 分钟**过期、**绑定设备**（A 手机的票 B 手机用不了）；
  伪造 / 过期 / 跨设备一律被拒 —— 下载接口**不接受路径**，只接受票。
- 支持 `Range`（206）⇒ 下载管理器可以"继续"。断点续传时票据保留到过期（否则"继续"会 404）。
- 非 ASCII 文件名走 RFC 5987（`filename*=UTF-8''…`），手机上下载下来还是中文名。
- 目录会被明确拒绝（`这是一个目录，不能直接下载`），而不是给一个 0 字节的"文件"。

**上传**（「＋」→「传到电脑」）：
- 落点 = **当前会话的工作区根目录**（可选子目录）。抽屉里**先显示**电脑上的绝对路径、
  大小上限、以及"重名不覆盖"的策略 —— 用户看得到才敢传。
- 安全边界：**只写工作区之内**，`..` 逃逸一律 403（与内核自己的 `list` 同一条边界）；
  文件名清洗（去分隔符/控制字符/Windows 保留名）；**重名自动 `-1`/`-2`，绝不覆盖**；
  写一半出错就**删掉残file**（半个文件比没有文件更坏）。
- 传完给出 `@` 提及文本，可直接一键引用让模型去读。

⚠️ **安全边界要说清**：上传让手机端获得了"能往电脑磁盘写字节"的能力。
这不是漏洞（正是用户要的能力），但 token 的保密等级应当按**等于电脑操作权**来看。
本插件仍然没有 TLS，局域网内明文 —— 公共 Wi-Fi 下别开着。

**⑦ 跨工作区（2026-09-22）**

「选电脑文件」和「传到电脑」两个抽屉顶部都有**工作区切换条**（本会话 / DSH工作区002 /
deepseek-workspace / DeepSeek-Workspace），点一下就在三个工作区之间换 —— 浏览、下载、
上传都跟着换。只有一个工作区时不显示这条（免得是噪音）。

- **为什么这件事能做成**（是官方设计允许的，不是绕过限制）：
  `WorkspaceFileScope` 是 `{sessionId, workspaceRoot}`，而 **`workspaceRoot` 是调用方给的**
  （`dsh-api-workspace-files/lib/index.js:555`）；所有方法的边界都拿这个字段去 confine
  （`confine()` 第 566-572 行：`if (!ctx.fs.contains(root, target)) throw outside-workspace`）。
  ⇒ **换一个 root 就换一个工作区，而边界仍由内核强制执行。**
- **我们额外加的那道闸**（比内核更严，**绝不能删**）：手机传的 root **必须命中已注册工作区**
  （依据官方 `workspaceController` 的 baseline，与「新建会话」同一个来源）。
  传 `C:\Windows` / `C:\Users` 一律被拒 —— 浏览、下载、上传**三条路各挡一次**
  （上传那条尤其重要：真正写字节的是 `POST /api/file/ul`，手机可以跳过 RPC 直接 POST）。
- **本会话工作区走另一条路**：`sessionFileReferences.list()`，它带官方排除表
  （`.git`/`node_modules`/`dist`…）且支持模糊搜索，看起来更干净。
  但它把索引钉死在 `agent.session.header.cwd`（同文件 387 行），**没有换根的口子** ⇒
  别的工作区只能走 `workspaceFiles.list()`。
- **跨工作区的 `@` 提及用绝对路径**（不是相对路径）。因为官方 `@` 的语义是
  "relative to the workspace root"（即**本会话**的根）—— 拿别的工作区的相对路径
  在当前会话里根本解析不到，模型会去找一个不存在的文件。
  绝对路径这条路官方是支持的：`read`/`readAll`/`stat` 都**允许工作区外路径**。

## 诚实的边界（**先看这段再决定要不要开着**）

- **没有 TLS，局域网内是明文。** 配对码与 token 在同一 Wi-Fi 下可被嗅探。
  **在家用 Wi-Fi 下可以接受；不要在公共 Wi-Fi / 公司网络里开着。**
- **服务监听 `0.0.0.0`** ⇒ 同一局域网内谁都能连到那个端口。安全性完全靠
  **一次性配对码（60 秒、用过即废）+ 随机 token（256 bit）**。
- **配对成功后，那台手机拥有与电脑端同等的操作能力**：能发提示词、能中断任务、
  **能批准工具调用**、**能改权限档位**、**能往工作区写文件**（见 ⑥ 文件互传）。
  本插件**不做**按设备的能力裁剪，也没有"只读模式"。
- **审批桥接的三条规则**（都关系到"会不会把电脑端卡住"，代码里有详细注释）：
  1. **没有手机在线时立刻让位**给官方其它 answerer —— 否则电脑上的审批框会不再弹出；
  2. **有手机在线但没人回答 ⇒ 90 秒后让位**，**不是自动同意**（自动同意 = 安全倒退）；
  3. 手机点「拒绝」会真的返回 `rejected`；**刻意不提供"永远同意"**（那需要持久化策略，
     风险面完全不同）。
- **token 现在会落盘**（`devices.json`，2026-09-22 为"免重扫"改的）。这是**有意放宽**的取舍：
  旧版 token 只在内存 ⇒ 重启内核就要重扫，用户嫌烦。代价是"拿到这个文件 = 拿到电脑上
  Agent 的操作权"。缓解：文件权限跟随用户 profile、内容只有"不透明 token → 设备名"、
  点「全部断开」会**立刻清空并写盘**、且它**不进 git、不进上传包**。
- 手机端**不能**：选 Agent 预设、拖拽/粘贴附件（只支持点选文件）。
- **没有推送通知**：手机锁屏后不会提醒你有新输出，要自己切回页面看。
- 手机端页面是 `http://`（非安全源）⇒ 浏览器里"添加到主屏幕"只能得到**书签快捷方式**，
  不是独立窗口；**要真正的独立 App 体验就得装那个壳**。

## 上一版（qwen 做的那个）为什么"装不上去"

> 结论：**不是"装不上去"，是从没被接进装载链，而且代码本身跑不起来。**
> 五处硬伤，每一处单独都足以致命。留在这里是为了以后别再犯。

| # | 硬伤 | 证据 |
|---|---|---|
| 1 | **宿主半边连语法都不合法** | `node --check desktop/index.js` → `SyntaxError: Unexpected token 'export'`，崩在 `export interface Config {` —— TypeScript 类型语法写进了 `.js` |
| 2 | **浏览器半边有顶层 `export`** | 客户端 bundle 是以**经典脚本**加载的（`dsh-client-modules/lib/client.js`：`createElement("script")` + `.src`，没有 `type=module`）⇒ 顶层 `export` 是语法错误，脚本**静默加载失败**、插件根本不出现 |
| 3 | **依赖根本不存在** | `import jwt from 'jsonwebtoken'`，而全盘扫 `profiles` 下 **jsonwebtoken / qrcode 一个都没有** ⇒ 必然 `ERR_MODULE_NOT_FOUND` |
| 4 | **`inject` 声明了不存在的包名** | 要求 `@deepseek-ai/dsh-client-command`，实际只有 `dsh-client-ui-commands`；且缺 `external` |
| 5 | **客户端半边压根没注册槽位** | 返回 `{inject: (ctx) => {…}}` —— 契约要求 `inject` 是**字符串数组**、`apply` 才是函数；全文 `ctx.slots.inject/register` **0 处**，只往 `document.body` 挂了个 div |

另外它还被 `profiles/web/package.json` 的 `dependencies` 与 `dsh.profile.bundles` **双双遗漏**
（两处都没有它）⇒ 内核按那个列表组合 profile，它永远不会被加载。端口 3110 也无监听。

**就算语法全修好，功能也还不通**（4 个语义缺口）：

1. PWA 发不出去：服务端只实现了 `/health`、配对、`/ws/mobile`，**没有静态文件处理**，默认 404
2. 一次性码永不变：`Date.now() + 5000 < Date.now() + this.CODE_TTL_MS` **恒为真**，与"60 秒轮换"完全相反
3. 手机永远连不上：服务端要求 WS 握手带 `Authorization: Bearer`，而浏览器 `new WebSocket()` **无法设置请求头**
4. 二维码用外网 `api.qrserver.com` 生成，且编的是**裸配对码不是 URL** ⇒ 断网即废、扫了也没法直接跳转

## 真跑时抓到的四个坑（都留了注释）

| 坑 | 表现 | 怎么抓到的 |
|---|---|---|
| `cordis.patch.yml` 的 `name` 写成显示名 `'Mobile Remote Plugin'` | **整个 profile 起不来**、界面退到状态页：`failed to import loader entry dsh-int-mobile-remote (Mobile Remote Plugin): Cannot find package 'Mobile Remote Plugin'` —— `name` 是 loader 用来 `import` 的**模块标识符**，不是给人看的 | 真跑第一次就抓到，日志原文在 `shell.log` |
| 客户端 `inject` 写成**包名** `['@deepseek-ai/dsh-client-ui-slots']` | 插件**永远停在 pending**、界面里什么都没有、**自己一行代码都没跑所以也不报错**：`web boot: 1 entry did not activate / pending (waiting for service: …)`。这里要的是 **cordis 服务名**（`'slots'`） | 写了个探针脚本接 CDP 抓 `Runtime.exceptionThrown` 与控制台 |
| 悬浮按钮**只把弹窗 portal 到 body**，按钮本身留在 `shell.overlay` 里 | 按钮被关在 `shell.overlay` 的 **z-index:20** 层叠上下文里 ⇒ 自己写 `z-index:9998` 也没用，官方那个 `z-index:1000` 的根遮罩盖在它上面。**用 `getBoundingClientRect()` 判是假 PASS**（矩形完全正常） | `document.elementFromPoint(按钮中心)` 命中的是 `_mask_w1urq_14`（别的元素）⇒ 与项目 AGENTS.md §5 那条完全吻合 |
| **测试夹具**里那个 1×1 PNG 是坏的 | 内核报 `Unsupported or malformed image data.`，我一度以为是插件的问题 | 用 sharp 逐步复现：`metadata()` **能过**、`raw().toBuffer()` **失败**（`vipspng: libpng read error`）⇒ 那个流传很广的 base64 的 IDAT 其实是坏的。换成 sharp 现生成的 PNG 即通过 |

> ★ 第二、三条合起来是一条教训：**"插件在界面里看不见"** 有三种互不相干的病因
> （bundle 没下发 / `apply` 抛错 / `inject` 等服务等不到），
> **"图片发不出去"** 也可能是夹具坏而不是代码坏 —— 都必须靠真跑 + 独立手段分开归因。

## 源码怎么读（**2026-09-21 起按"电脑侧 / 手机侧"分层**）

```
desktop\              ★ 电脑侧（**上传 / 发布 / 进 git 的就是这层**）
├─ index.js           宿主半边：局域网服务（配对/SSE/RPC）+ 审批桥接 + 同源路由
├─ client.js          电脑端界面：右下角悬浮按钮 + 双二维码弹窗（手写单文件 bundle）
├─ qr.cjs             vendor 的二维码编码器（MIT，原样，未改一行）
└─ qr-LICENSE.txt     上一行的许可证
phone\                ★ 手机侧（网页，宿主运行时**现读**这里的文件发给手机）
├─ index.html / app.js / styles.css / manifest.webmanifest
android\              手机侧的 App 壳（零第三方依赖；**不进上传包**，见下）
web\                  ⚠️ 过渡期兼容副本（给分层**前**启动的旧宿主读的）——重启一次客户端后可删，
                      见 web\README-为什么存在.md
```

**为什么 `phone/` 必须留在包里、而 `android/` 不进**：手机页不是打包时嵌进客户端的，
是宿主半边用 HTTP **现读现发**——所以 `phone/` 必须跟着宿主一起被装到用户机器上；
而 App 壳要自己编译成 APK 再装，打进插件包只会白占体积（且 `android/build` 里有
232 字符深的路径，进包有真实风险）。这条取舍已由 `package.json` 的 `files` 白名单固化。

**上传 / 发布**：走第三工作区的插件上传器
（`D:\DSH工作区002\1.DSH插件上传器\`）。
`node scripts\publish-only.mjs <本目录> [说明]` = **只发布到远端、不动本机 profile** ——
本机 profile 仍钉在 `link:` 联接上，改这里的源码**依旧即时生效**。
（要"装成归档副本"才用 `upload`，那会切断"改源码即时生效"。）

`desktop/index.js` 顶上写着三条刻意的设计决定（**为什么不用 WebSocket**、
**为什么零依赖**、**为什么 token 不落盘**），`desktop/client.js` 顶上写着它踩过的坑。
读之前先读那两段注释，能省很多时间。

### 「设置页投影到手机」的可行性结论（2026-09-22 逐行查过内核源码）

**结论：技术可行、约 150–200 行、不需改内核、不需新依赖**，但有一个**必须先正视的安全问题**。

| 问题 | 结论（含出处） |
|---|---|
| 官方 UI 谁提供 | `dsh-web-app` + `dsh-host-frontend-static`，走同一个 `webServer`，但抢的是 `registerFallback` 那一座兜底座位（`dsh-host-frontend-static/lib/index.js:87`）。**没有路由前缀** —— 它就是"所有未被具名路由认领的路径" |
| 能不能也用 fallback | **不能**：座位只有一个，第二次注册直接抛错（`dsh-host-webserver/lib/index.js:205-211`）。`{kind:'prefix', path:'/'}` 也**不是**通配（只认根路径，见 `:327` 的判定）⇒ **不要用 webServer 做代理** |
| 那怎么做 | 改造本插件已有的 `0.0.0.0:3110` `node:http` 服务器成透明反代 —— 它看得见全部路径，不受路由表约束 |
| 拿凭据 | **能**，且是官方公开 API：`ctx.get('connection').authenticatedUrl('http://127.0.0.1:'+port)`（`dsh-client-connection/lib/index.js:561-564`）。**本机已有先例**：`dsh-plugin-install/lib/index.js:8766-8771` 就是这么干的 |
| 鉴权机制 | `?token=<launchToken>` → 303 + `Set-Cookie`（`:386-425`）；之后只认**签名 Cookie**（`dsh-auth-<sha256(authority)>`，HMAC-SHA256，`:280-301`）。⚠️ token **只在 `GET /` 上有效**（`:392`），不能直接用于 `/api/*` |
| **真正的拦路虎** | 官方有 `isTrustedApiRequest` 围栏（`:201-215`）：`Host` 必须回环或受信、`sec-fetch-site: cross-site` 直接 403、`Origin` 必须与 Host 同源。⇒ 代理**必须改写 Host 为 `127.0.0.1:3105`、剥离/改写 Origin 与 `sec-fetch-*`** |
| 传输协议 | **WebSocket**（`/api/remote.mux`，`dsh-api-gateway/lib/index.js:460-471` 注册 upgrade），不是 SSE。客户端用**当前页面 origin** 拼 `ws://<origin>/api/remote.mux`（`dsh-api-gateway/lib/client.js:541-547`）⇒ 对代理友好 |
| ⚠️ 最阴的坑 | 本插件的 LAN 服务器**没有 `upgrade` 监听器**（只有 `error`）⇒ **只转发 HTML 的话页面能打开、但 WebSocket 连不上，界面是死的**，而且**不报错、只是不动**。这是排查成本最高的一种坏法 |
| 两个细节 | ① 官方首页强制 `<base href="/">`（`dsh-host-frontend-static/lib/index.js:85`）⇒ **只能挂根路径**，不能挂 `/dsh/` 子路径；② 首页里的 `__DSH_CONNECTION_RECOVERY__` 必须原样转发，不能自己重写 HTML |
| 既有先例 | **没有任何插件做过**（全库检索：`kind:'prefix'` 0 命中、`registerFallback|registerUpgrade` 在插件目录 0 命中、无任何代理官方路由的实现） |

**⚠️ 安全边界（这是我不建议草率做的主因）**：
这条路等于把「能执行任意代码的 Agent」暴露给**整个局域网**。官方自己在
`dsh-web-app/lib/startup.js:40` 明确拒绝 `--host 0.0.0.0`，理由原文是
"it would expose remote code execution to the network"。
**如果做，必须至少加一层自己的鉴权** —— 本插件现有的一次性码 + token 机制可以直接复用，
但要明确：这比现在的"只能发消息/批审批"高一个量级（手机将能装插件、改任意设置）。
