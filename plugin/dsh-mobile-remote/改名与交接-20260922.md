# 接手必读：这个插件改过名（2026-09-22）

> **给对话/人的一句话**：`dsh-mobile-remote` 已改名为 **`dsh-int-mobile-remote`**，
> 版本 `0.3.0 → 0.4.0`。**仓库里的目录名刻意保持旧名没动** —— 别"顺手改回去"，
> 那会当场弄坏已装的插件。下面是为什么、以及改名要同时动哪几处。

---

## 一、为什么改名

查公开生态时发现这个名字**已经被别人占用**：

| 位置 | 占用者 | 时间 |
|---|---|---|
| npm | `dsh-mobile-remote` **0.1.0**，author **good-boy4069** | 2026-08-16 起 |
| dsh-plugin.org（社区插件市场，非官方） | 同名收录 **12 个**（good-boy4069 / az7627 / feiyang-dev …），**没有一个是我们的** |

后果：我们自己分发没问题（走自己的索引 + sha256 + 本地包），但在公开生态里**等于没有身份**。
所以加 `dsh-int-` 前缀拿到一个干净的名字。

（同批改名的还有 `dsh-archive-manager → dsh-int-archive-manager`。
`dsh-multi-session` / `dsh-plugin-uploader` 在 npm 与社区站上都干净，**没动**。）

## 二、★ 改名必须同时改这几处，漏一处内核直接起不来

| # | 位置 | 改成什么 | 漏了会怎样 |
|---|---|---|---|
| ① | `package.json` 的 `name` | `dsh-int-mobile-remote` | 内核按 profile 里的键解析包名，对不上就找不到包 |
| ② | `cordis.patch.yml` 的 `id` **与** `name` | 同上 | 报 `declares no dsh.bundle`；`name` 是 loader 的**模块标识符**，写成显示名会 `ERR_MODULE_NOT_FOUND` |
| ③ | `desktop/index.js` 的 `export const name` | 同上 | bundle 公告的名字与实际不符 |
| ④ | `desktop/index.js` 的 `ROUTE_PREFIX` | `/dsh-int-mobile-remote` | 同源路由与客户端拼接的地址对不上 |
| ⑤ | `desktop/client.js` 的 `__ModuleLoader__.load({ id })`、`PLUGIN_ID`、`ROUTE` | 同上 | 浏览器半边注册不上 / 拿不到状态 |
| ⑥ | **用户的 profile 三处契约** | 键名 / bundles 条目 / `node_modules` 联接 | 装了也加载不了（见下） |

第 ⑥ 处不在本目录里，在用户的 DSH 家里：

```
<DSH_HOME>\profiles\web\package.json   → dependencies 的键、dsh.profile.bundles 的条目
<DSH_HOME>\profiles\web\node_modules\dsh-int-mobile-remote   → 目录联接（指向本目录）
```

**换包名不能热更**（要重新解析 `node_modules`）⇒ 用户必须**重启一次客户端**。

## 三、★ 目录名为什么没跟着改（别改）

仓库里的 `plugin\dsh-mobile-remote` 是一个**目录联接**，指向本体
`D:\DSH工作区002\3.dsh-mobile-remote`。而：

- 已装插件在 profile 里的 `link:` 是**写死的绝对路径**；
- `node_modules` 里那个联接也指过来。

两边都是绝对路径 ⇒ **改目录名 = 当场弄坏这个插件**（全局规矩：联接两头都不能改名/搬家）。
所以：**包名是新名，目录名与路径一律保持旧名。**
外壳的验收脚本因此把两者拆成两个常量：`PLUGIN_NAME` / `PLUGIN_DIR_NAME`。

## 四、名字的映射表（照着改，别猜）

| 旧 | 新 |
|---|---|
| `dsh-mobile-remote`（包名） | `dsh-int-mobile-remote` |
| `/dsh-mobile-remote`（路由前缀） | `/dsh-int-mobile-remote` |
| `dsh-mobile-remote`（目录名，**不动**） | `3.dsh-mobile-remote`（本体，**不动**） |
| 版本 `0.3.0` | `0.4.0` |

### ★ 要分清哪些**没变**（这几处最容易过度替换）

- **手机页面代码不碰路由前缀**：`phone/app.js` 走的是 `/api/rpc`、`/api/events`、
  `/api/pair/submit`，**从来没有** `/dsh-mobile-remote` 这个字符串
  ⇒ 改 `ROUTE_PREFIX` **不需要重新编译 APK**，手机上也不用重装。
- **Android 侧不认包名**：`MainActivity.java` 的 `urlFromIntent()` 只要求 `startsWith("http")`，
  首页地址 `/` 与二维码里的完整 URL 都由桌面侧生成 ⇒ APK 与包名无关。
- 手机页面是**宿主每次现读磁盘**托管的（`PHONE_DIR`），改了 `phone/` 里的文件，
  手机上刷新页面就生效，不用重打包。

## 六、踩过的坑（别重复）

1. **验收脚本的"源码完整性清单"必须跟着包内结构走。**
   `scripts\plugin-check-mobile-remote.js` 里原来写死 `lib/index.js`、`web/index.html` 等
   改名前的路径，而插件早已分层成 `desktop/` + `phone/` ⇒ 一进门就报
   「插件源码不完整：缺 lib/index.js」，**看起来像插件坏了，其实是清单过时**。
   现在改成按 `package.json` 的 `exports` 解析入口。（这一条是 2026-09-22 改名时抓到的。）

2. **别把 `PLUGIN_NAME` 同时当包名和目录名用。** 合成一个常量就会出现
   "改了包名，脚本再也找不到源码"这种静默故障。

3. **`npm pack` 出的 tgz 里 `package.json` 是改名后的名字**——改名后**必须重发**，
   否则从仓库装出来还是旧包名，会和已改名的 profile 并存（两个插件抢同一批界面槽位）。
